# Kalzit 0.5.1

Organization membership by invitation, leaving an organization and safer sign-ins, a security fix
for plugins on several servers that share one database, and a release manifest that reads the
same everywhere.

## Improved

- People who already belong to an organization join another one only by accepting an
  invitation; an admin can no longer add them directly. The other organization's sign-in rules
  (password sign-in off, a required second factor) apply to their account, so they decide
  themselves. Accounts that belong to no organization yet are still added directly. When "Add
  member" names a person who already has an organization, it says so and offers to send an
  invitation instead.
- SCIM no longer links an account that belongs to another organization; the request is refused
  and the SCIM card names the reason. Invite the person, and SCIM links the account once they
  accepted.
- Everyone can leave an organization themselves: Settings > Profile lists your organizations with
  "Leave…". It works with any open session, also while that organization's rules no longer let
  your password sign you in. The last owner of an organization cannot leave it.
- An organization's sign-in rules (password sign-in off, a required second factor) apply only to
  members who joined by their own choice: by invitation, as its creator, through its SCIM or a
  provider's group mapping. Members an admin added, and all memberships from before 0.5.1, keep
  signing in as the server allows; they keep their membership and can leave it.
- A person who left an organization, or whom an admin removed, is not added back by that
  organization's SCIM, and SCIM never adds a person who belongs to another organization.
- The first sign-in through a provider that links your account by its email address now asks for
  that account's second factor, or its password when it has none, once. A provider's word for a
  second factor does not count in that sign-in.
- Creating or changing a sign-in provider that trusts the provider's email addresses or second
  factors asks the admin to confirm their own second factor first.
- Service account tokens can no longer change an organization's second factor rules or turn
  password sign-in off.
- The release's manifest file now reads the same in every text encoding: shortened lines of the
  update notes end in "…", and umlauts and other characters show correctly in any tool that opens
  the file, also in Windows PowerShell.

## Fixed

- While password sign-in is off for an account, the right password is answered like a wrong one
  and counts against the sign-in limits, so passwords cannot be tested there. The sign-in page
  still shows the providers.
- A directory (LDAP) sign-in that Kalzit refuses is answered like a wrong password and counts
  against the sign-in limits; the reason is in the audit log and the person's recent sign-ins.
- With several Kalzit servers on one database, every server checks a plugin package itself before
  it runs it: a damaged or changed archive, a package directory outside the packages folder, a
  signature by another key than the one recorded at the installation, or a key that is not trusted
  or was removed stops the plugin on that server, and the refusal is in the audit log. Protect the
  database credentials like admin credentials: whoever may write the database counts as a server
  admin.

## Checklist for Windows (manual)

- Invitation instead of adding: with two organizations, try to add a member of the first one to
  the second under Verwaltung > Mitglieder > "Mitglied hinzufügen…". Check that the dialog says the
  person joins by invitation and that "Stattdessen einladen" opens the invitation with the address
  and role filled in.
- Leaving: sign in as that person after accepting, open Einstellungen > Profil, choose
  "Verlassen…" for the second organization and confirm; check that the organization is gone from
  the workspace menu. As the only owner of an organization, check that leaving it is refused with
  a clear message.
- Linking by email: with an OpenID Connect provider and an existing local account of the same,
  verified address, sign in through the provider and check that Kalzit asks once for that
  account's password ("Bestätige, dass es dein Konto ist"), and not again at the next sign-in.
- Plugins on two servers: run two Kalzit servers on Windows with the same PostgreSQL database,
  install and enable a signed data source plugin on the first and check that it runs on the second
  within a minute (Verwaltung > Plugins shows it running there).
- Install an update of the plugin on the first server and check that the second server runs the
  new version within a minute and that the audit log has no "plugins.package_refused" entry.
- Updates: open Verwaltung > Updates while a release with long update notes is offered, and check
  that shortened lines end in "…" and that umlauts show correctly.
