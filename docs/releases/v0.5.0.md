# Kalzit 0.5.0

The parts of 0.5.0 that were finished earlier shipped with 0.4.2; see its notes.

## Improved

- Two-factor sign-in: protect your account with passkeys (fingerprint, face, device PIN or a
  security key), an authenticator app (six-digit codes) and ten recovery codes, under Settings >
  Sign-in and security. After the password, Kalzit asks for one of them; nothing of the app opens
  before. Removing a method, new recovery codes and a new password ask for a fresh confirmation.
- Server admins can require a second factor for admins or for everyone (Settings > Sign-in), and
  choose the allowed methods; organizations can be stricter for their members. Whoever must have
  one and has none sets it up at the next sign-in, in three steps.
- Five wrong codes lock the second step of an account for 15 minutes; members and users show each
  person's methods, a missing second factor and a running lockout.
- Admins can reset another person's second factor after confirming with their own; the reset
  signs the person out everywhere and is recorded in the audit log.
- Usage insights under Administration > Usage (Verwaltung > Nutzung): the most viewed dashboards,
  the slowest panels (median and 95th percentile), panels and data sources with errors, the cache
  hit rate per data source, dashboards nobody opened in 30 or 90 days, and the trend over the last
  24 hours, 7, 30 or 90 days. Every row links to its dashboard, panel or data source.
- Usage is counted per dashboard, panel and data source only, never per person: no user, session
  or address is stored for it. Organization admins see their organization, server admins every
  organization or one.
- Settings > Storage and retention: turn "Record usage" off (applies at once, with undo) and choose
  how long usage counts are kept (90 days at most, the default).
- Hierarchy panels can use ELK (the Eclipse Layout Kernel) instead of Kalzit's own layered layout:
  under Layout in the panel options, pick "ELK layered" and set the direction, node and layer
  spacing and the edge routing. Kalzit's layout stays the default; ELK loads only when a panel
  uses it, gives the same result the same layout every time, and if it cannot run the panel shows
  Kalzit's layout and says so.

## Checklist for Windows (manual)

- Two-factor sign-in with Windows Hello: open Kalzit on Windows 11 by its host name (not an IP
  address), add a passkey under Settings > Sign-in and security with Windows Hello, sign out and
  sign in again with the passkey. Repeat with an authenticator app on a phone.
- Usage: open a dashboard with the sample SQLite source twice, wait 20 seconds, and check that
  Administration > Usage lists it under "Most viewed dashboards" with 2 views and its panel under
  "Slowest panels", and that the link opens the dashboard. Turn "Record usage" off in Settings >
  Storage and retention, open the dashboard again, and check that the views stay at 2. Stop the
  Windows service right after opening a dashboard and start it again: the view is counted.
- Open a dashboard with a hierarchy panel on the Windows server in Edge, set Layout to "ELK
  layered" and Direction to "Left to right", save, and check that the tree is drawn from left to
  right without a note that ELK could not run; reload and check that it looks the same.
