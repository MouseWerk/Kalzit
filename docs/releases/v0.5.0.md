# Kalzit 0.5.0

The parts of 0.5.0 that were finished earlier shipped with 0.4.2; see its notes.

## Improved

- Two-factor sign-in: protect your account with passkeys (fingerprint, face, device PIN or a
  security key), an authenticator app (six-digit codes) and ten recovery codes, under Settings >
  Sign-in and security. After the password, Kalzit asks for one of them; nothing of the app opens
  before. Removing a method, new recovery codes and a new password ask for a fresh confirmation.
- Server admins can require a second factor for admins or for everyone (Settings > Sign-in), and
  choose the allowed methods; organizations can be stricter for their members. Whoever must have
  one and has none sets it up at the next sign-in, in three steps.
- Five wrong codes lock the second step of an account for 15 minutes; members and users show each
  person's methods, a missing second factor and a running lockout.
- Admins can reset another person's second factor after confirming with their own; the reset
  signs the person out everywhere and is recorded in the audit log.
- Windows installer: `kalzit-0.5.0-windows-x64.msi` installs Kalzit as the Windows service
  "Kalzit", running under its own account `NT SERVICE\Kalzit` and starting with Windows. The wizard
  asks for the port, the data folder (`%ProgramData%\Kalzit\data` by default) and HTTPS (off, a
  self-signed certificate or your own certificate files), and opens the firewall only when you
  tick it. Only Administrators and the service can open the data folder, only Administrators can
  change the program folder, and the service runs without the privileges that would let it act as
  another account.
- The installer's wizard speaks German on a Windows with German as its display language and
  English otherwise, from the same MSI file; `TRANSFORMS=:1031` on the msiexec command line
  chooses German on any Windows.
- The installer refuses folders someone else could have prepared (a configuration or data folder
  others may open or change, a link or junction on the way, a program folder with other files)
  and says in its log and in the event log what to fix.
- Silent installations: every setting of the wizard is also an MSI property (`PORT`, `DATADIR`,
  `HTTPS`, `HTTPSPORT`, `CERTFILE`, `KEYFILE`, `FIREWALL`, `SELFUPDATE`), for example
  `msiexec /i kalzit-0.5.0-windows-x64.msi /qn PORT=8080 FIREWALL=1`.
- Without the installer: `kalzit service install` sets up the same Windows service for a
  `kalzit.exe` you copied yourself, and `kalzit service uninstall` removes it.
- Updates on Windows: install the next MSI package over the current one; settings and data stay.
  Opt in with `SELFUPDATE=1` and Kalzit installs updates on its own as the service, as on Linux
  (stop, new version, start, back to the previous one if it does not start properly); the
  installation guide explains what that allows the service account.
- Upgrading from a data folder that someone else than Administrators owns or may open (for
  example one an earlier `kalzit serve` made as a standard user) is refused: the installer says
  to move the folder aside, then install again.
- Uninstalling keeps your data and settings for a later installation, unless you choose to
  remove them (or pass `REMOVEDATA=1`).
- The service writes its log to `logs\kalzit.log` in the data folder; problems before that, such
  as a broken `kalzit.toml`, show in the Windows event log under the source "Kalzit".
- A plugin whose program file changed after its installation no longer starts; install it again.
- Settings, About warns server administrators when `kalzit.toml` holds the database password,
  which everyone who may read the file sees.
- Packages for Linux: every release has a deb (Debian, Ubuntu) and an rpm (Fedora, RHEL, Rocky,
  Alma) that install Kalzit as the systemd service `kalzit`, running as its own system account
  with a hardened unit, the configuration in /etc/kalzit/kalzit.toml and the data in
  /var/lib/kalzit. The secrets key is created in the system credential store, encrypted where the
  system supports it. Removing the package keeps your data; `apt purge` deletes it.
- Installed from a package, the Updates page shows the command that installs a new release with
  apt or dnf, and the package restarts the service.
- The deb and rpm are listed with their SHA-256 and signature in the release's signed manifest.
- HTTPS certificates from Let's Encrypt or any other ACME certificate authority: under Settings >
  Network, HTTPS and proxy (Einstellungen > Netzwerk, HTTPS und Proxy), enter the names, choose
  HTTP-01 (port 80) or TLS-ALPN-01 (port 443) and save. Kalzit orders the certificate, serves it
  without a restart and renews it before it expires. A staging option lets you try the setup
  first.
- The certificate settings are saved in one step after a check of the certificate authority and
  the names; "Test connection" checks without saving, and every problem is shown at its field.
- The certificate card shows the names, the issuer, until when it is valid, when it is renewed,
  and after a failure the reason and the next attempt; "Renew now" orders at once. Failed
  attempts are retried with growing pauses, and every certificate and failure is in the server
  audit log.
- With ACME on and without certificate files, HTTPS starts with a temporary self-signed
  certificate until the first one is issued; with ACME off, Kalzit still asks for the files. With
  HTTP-01 the certificate can be ordered before HTTPS is turned on.
- `kalzit sandbox-check` lists the protections plugins get on a Linux system.
- Query cache on the server: dashboards that are opened again, switched back to or auto
  refreshed show kept answers instead of asking the database again. Answers are kept per person,
  so nobody ever sees an answer someone else's rights produced. The Refresh button always asks
  the database.
- Every data source has a "Cache" section: "Cache answers on the server" and "Keep answers for
  (seconds)" (60 by default). On by default for SQL databases, Elasticsearch and OpenSearch, Neo4j,
  Memgraph and TigerGraph; off for Prometheus, MongoDB, files, HTTP APIs and plugins.
- Ranges that end now ("Last 6 hours") move back to a round step while the cache is on, so loads
  close together share one answer; the newest point is at most one step (the panel's interval,
  at most the source's cache time) old.
- Settings > Data sources and targets (Verwaltung > Einstellungen): turn the query cache on or off
  for the server, set its memory, see how many answers it keeps and how often loads came from it,
  and empty it.
- Inspect shows per query whether the answer came from the server cache and how old it is, or
  that it ran in the data source and how long it is kept.
- Several Kalzit servers on one PostgreSQL database: run two or more behind a load balancer, so
  one can stop while the others keep answering. Sticky sessions are not needed. Settings,
  rights, data sources, plugins and certificates changed on one server reach the others within
  about a second; a session ended on one server is refused on all of them at once.
- One server leads and runs what must run once: retention cleanups, the plugin catalog refresh,
  the daily update check and HTTPS certificate orders. When it stops, another server takes over
  within seconds; after a crash within 20 seconds.
- Verwaltung > Instanzen (Administration > Instances) lists the servers with their host,
  version, start, last heartbeat and which one leads, and warns while they run different versions.
- With several servers, a certificate from Let's Encrypt or another ACME authority is ordered
  once and served by every server; plugins installed through one server run on all of them.
- With several servers, Kalzit does not install updates on its own; Updates says so. Update one
  server after the other with its package; the operations guide (docs/operations/high-availability.md)
  describes the load balancer, health checks and rolling updates.
- A second Kalzit server started on the same SQLite database now stops at once with a clear
  message instead of running next to the first.
- New data source ClickHouse: SQL over the HTTP interface with the usual SQL editor, macros and
  variables. Every query runs read-only on the server and is checked before it is sent.
- New data source InfluxDB for 1.x, 2.x and 3.x: Flux, InfluxQL and SQL (3.x), chosen per query in
  the editor, with the dashboard's time range (`v.timeRangeStart`, `$__timeFilter`) and
  suggestions for measurements, fields and tags. Queries that would write are refused.
- New data source Loki: log queries show one entry per log line with its time and labels, metric
  queries a time series; the editor suggests labels and their values.
- InfluxDB and ClickHouse show their logos in the list of kinds.
- Usage insights under Administration > Usage (Verwaltung > Nutzung): the most viewed dashboards,
  the slowest panels (median and 95th percentile), panels and data sources with errors, the cache
  hit rate per data source, dashboards nobody opened in 30 or 90 days, and the trend over the last
  24 hours, 7, 30 or 90 days. Every row links to its dashboard, panel or data source.
- Usage is counted per dashboard, panel and data source only, never per person: no user, session
  or address is stored for it. Organization admins see their organization, server admins every
  organization or one.
- Settings > Storage and retention: turn "Record usage" off (applies at once, with undo) and choose
  how long usage counts are kept (90 days at most, the default).
- Hierarchy panels can use ELK (the Eclipse Layout Kernel) instead of Kalzit's own layered layout:
  under Layout in the panel options, pick "ELK layered" and set the direction, node and layer
  spacing and the edge routing. Kalzit's layout stays the default; ELK loads only when a panel
  uses it, gives the same result the same layout every time, and if it cannot run the panel shows
  Kalzit's layout and says so.
- Single sign-on with OpenID Connect (Keycloak, Authentik, Entra ID and others): under
  Administration > Sign-in (Verwaltung > Anmeldung), add a provider, test the connection and a
  test sign-in, then save. The sign-in page shows "Sign in with <provider>" first; accounts are
  created at the first sign-in.
- Group mapping: the groups a provider sends give a role in an organization and a team. The
  highest role wins; "IdP decides" keeps role and membership in step with the provider and locks
  the role in Members, "Kalzit adds" gives a minimum role. People without a matching group get a
  default role or are refused.
- LDAP and Active Directory sign-in: under Administration > Sign-in (Verwaltung > Anmeldung), add
  a directory with its server (LDAPS or StartTLS), a service account, the base DN and the login
  name (`sAMAccountName`, `userPrincipalName` or email for Active Directory), test the connection
  with a sample person, then save. People sign in with their directory name and password in the
  usual form ("Email or username"); their account is created at the first sign-in, their
  directory groups give their roles like single sign-on groups, nested Active Directory groups
  can be followed, and Kalzit's own second factor applies. The service account's password is
  stored encrypted and never shown again.
- Directory sync: every night (or every 6 hours) Kalzit locks the accounts of people who left the
  directory, are disabled there or are in no mapped group any more, and unlocks them when they
  are back. It never deletes an account. When a sync would lock more than 10 % of the accounts
  (adjustable), it stops before changing anything, mails the server admins and shows the list;
  "Apply anyway" asks for your second factor.
- Password sign-in can be turned off for everyone except a break-glass admin, who signs in on the
  unlinked page /anmelden/lokal; every such sign-in is in the audit log. Organizations can turn
  password sign-in off for their members.
- Service accounts under Administration > Service accounts (Verwaltung > Dienstkonten): accounts
  for scripts and other systems, each with a role in its organization (never owner), and API tokens
  for them (`Authorization: Bearer kz_sa_...`). A token is shown once, stored only as a hash,
  expires after 90 days by default and after a year at the latest, can be limited to IP addresses
  and networks, and can be revoked at once. A token works only in its organization, with its
  account's role, and every created, revoked or refused token is in the audit log. The same page
  manages the organization's one SCIM token for the coming SCIM provisioning.
- Mail server: under Settings > Email (Verwaltung > E-Mail) enter server, port, STARTTLS or TLS,
  user and password and the sender, send a test mail, then save. The test mail shows what the
  server answered, the TLS version and until when its certificate is valid; a problem is shown at
  its field. The password is stored encrypted and never shown again. `[smtp]` in `kalzit.toml` or
  `KALZIT_SMTP_*` can set the mail server instead.
- Invitations: Members has **Invite** for one or several email addresses with a role and an
  optional team. With a mail server the people get a mail in their language; without one you get
  the links to pass on. Links work for seven days and once.
- Open invitations are listed above the members with role, team, who invited, until when they
  are valid and whether the mail was delivered or refused (with the mail server's answer); send a
  mail again (a new link, seven more days) or revoke it. Links to pass on can be copied again.
- Accepting an invitation: the link opens a page with the organization, role and team; a new
  person chooses a name and password and starts right in the organization, someone with an
  account signs in and joins.
- An account made from a link an admin passed on starts with its email address unconfirmed;
  Profile offers to confirm it by mail, with a link that only works signed in as that account.
  Until then it cannot be added to another organization by its address.
- Forgot password: the sign-in page leads to **Reset password**, which mails a link that works for
  60 minutes and once. The page answers the same whether or not an account has the address. The
  new password ends all other sessions; the second factor stays as it is.
- Admins can send a member the password link from the member's menu.
- Mails and links need the server's public address (`server.public_url`); without it Kalzit says
  so instead of sending links that point nowhere.

## Fixed

- A data source whose database is down now says so within a few seconds, naming the address
  and the cause ("Keine Verbindung zu 127.0.0.1:15432: Verbindung abgelehnt"), instead of a pool
  timeout after 10 seconds. A server that does not answer at all is reported after the connect
  timeout with the address. This applies to PostgreSQL, MySQL and MariaDB, SQL Server, Neo4j,
  Memgraph and a single MongoDB server; sources reached over HTTP (Prometheus, Elasticsearch,
  ClickHouse and others) name a refused address or a host name that does not resolve the same
  way, and a TLS failure says what failed instead of only "error sending request".
- After a database restarted, the first query no longer fails with "early eof": connections that
  broke while they waited are noticed and replaced, and a query that hits one runs once more on a
  fresh connection. When a connection does break during a query, the panel says that the
  connection was interrupted; the driver's own text is under Inspect.

## Checklist for Windows (manual)

- Two-factor sign-in with Windows Hello: open Kalzit on Windows 11 by its host name (not an IP
  address), add a passkey under Settings > Sign-in and security with Windows Hello, sign out and
  sign in again with the passkey. Repeat with an authenticator app on a phone.
- Installer wizard: run the MSI on a fresh Windows 11 and on Windows Server 2025, keep the
  defaults, and check that `http://localhost:3000` opens, that `setup-token.txt` in the data
  folder holds the setup code, and that the service "Kalzit" runs as `NT SERVICE\Kalzit`.
- Wizard settings: install with another port, a data folder on another drive, "Self-signed
  certificate" and the firewall ticked; check that HTTPS answers on 3443 (with the browser's
  warning), that Windows Defender Firewall has the inbound rule "Kalzit", and that the data
  folder's Security tab lists only Administrators and Kalzit.
- German wizard: on a Windows with German as its display language, run the MSI and check that
  every page is German (Servereinstellungen with HTTP-Port, Datenordner, HTTPS and "Port(s) in der
  Windows Defender Firewall öffnen", the last page with the Einrichtungscode note), that umlauts
  show correctly and no text is cut off; then remove it in Settings, Apps, run the MSI again,
  choose Entfernen and check the page "Kalzit entfernen" with its checkbox.
- Existing certificate: install with your own PEM certificate and key, open Kalzit over HTTPS,
  then save a renewed certificate over the files and check that the browser shows it within a
  minute.
- Code signing: check the publisher shown by the installer and in the properties of
  `kalzit.exe` (Digital Signatures); for an unsigned release, check the note in the release
  notes.
- Prepared folders: create `C:\ProgramData\Kalzit` as a standard user before installing and check
  that the installer stops with a message; do the same with the program folder `C:\KalzitTest`.
- Plugins under the service: install the example data source plugin and check that it starts and
  answers (the service runs with SeChangeNotifyPrivilege only).
- Update through the service: with this version installed by the MSI with `SELFUPDATE=1`,
  install the next release from Verwaltung > Updates and check that the service comes back with the new version within a
  minute; install a release that fails its health check and check that Kalzit returns to the
  previous version.
- Upgrade with the next MSI over this one: settings and data stay, the service runs afterwards.
- Uninstall in Settings, Apps: the service and the firewall rule are gone, the data folder and
  `kalzit.toml` stay. Then install again, run the MSI once more, choose Remove and tick "Also
  remove the data folder": the data folder and `kalzit.toml` are gone.
- Restart Windows with Kalzit running: it starts again on its own, and the log shows a clean
  stop before the restart.
- Start Kalzit with `server.https_addr` set and without `tls.cert_file` while ACME is off: it
  refuses to start and names the missing files. Turn ACME on with HTTP-01 first, then start with
  HTTPS: it answers with the temporary self-signed certificate (or the issued one) and the log
  says so.
- Settings > Network, HTTPS and proxy: the ACME card shows "Off"; turn it on with a name that
  does not resolve and save: the error appears at Names; without accepting the terms, at the
  terms.
- With a real name pointing at the Windows server and port 80 or 443 forwarded to it, choose Let's
  Encrypt staging and save: the certificate card turns to Valid, and the browser shows the staging
  certificate after a reload, without a restart.
- Restart Kalzit: the same certificate is served at once.
- `kalzit secrets rotate` with Kalzit stopped, then start: the certificate is still served.
- Add the sample SQLite source, open a dashboard with a table panel on it, open the panel's
  Inspect and check that it says "Ran in the data source; kept in the server cache for 60
  seconds". Reload the page and check that Inspect now says "From the server cache".
- Change a value in the SQLite file with another tool, reload the dashboard and check that the
  old value stays; press Refresh and check that the new value appears and Inspect says
  "Refreshed in the data source".
- Sign in as a second user in another browser, open the same dashboard and check that Inspect says
  "Ran in the data source" for that user's first load.
- In Settings > Data sources and targets check the "Query cache now" line, press "Empty cache" and
  check that the audit log shows "Query cache emptied".
- Turn "Cache answers on the server" off for the source, save, and check that Inspect no longer
  mentions the cache.
- Start `kalzit.exe serve` in a second console with the same data folder while the service runs:
  it stops at once and says that another Kalzit server runs on the SQLite database.
- Verwaltung > Instanzen with SQLite: one server, "This server" and "Leader", "Serves one server".
- Two Windows servers on one PostgreSQL database with the same `KALZIT_SECRETS_KEY`, behind a
  load balancer: Instanzen lists both and one leader; change a setting on one and check that the
  other shows it after a reload; stop the leading service and check that the other leads within
  half a minute; Updates says that each server is updated on its own.
- ClickHouse: run `clickhouse/clickhouse-server` in Docker Desktop (or WSL), add a ClickHouse
  source with `http://localhost:8123`, press "Test connection", then in Explore run
  `SELECT number FROM numbers(5)` and check that a table with five rows appears; check that
  `INSERT INTO t VALUES (1)` is refused.
- InfluxDB 2.x: run `influxdb:2.7` with an organization, bucket and token, add an InfluxDB source
  (version v2) with the token, test it, and in Explore run a Flux query with
  `range(start: v.timeRangeStart, stop: v.timeRangeStop)`; check that a time series appears and
  that a query with `to(bucket: "x")` is refused.
- Loki: run `grafana/loki`, push a few lines, add a Loki source with `http://localhost:3100`, test
  it, and in Explore run `{app="test"}`; check that each line appears as an entry with its time and
  labels and that typing `{app="` suggests the values.
- Usage: open a dashboard with the sample SQLite source twice, wait 20 seconds, and check that
  Administration > Usage lists it under "Most viewed dashboards" with 2 views and its panel under
  "Slowest panels", and that the link opens the dashboard. Turn "Record usage" off in Settings >
  Storage and retention, open the dashboard again, and check that the views stay at 2. Stop the
  Windows service right after opening a dashboard and start it again: the view is counted.
- Open a dashboard with a hierarchy panel on the Windows server in Edge, set Layout to "ELK
  layered" and Direction to "Left to right", save, and check that the tree is drawn from left to
  right without a note that ELK could not run; reload and check that it looks the same.
- Single sign-on: run Keycloak in Docker Desktop with a realm, a confidential client `kalzit`
  and a `groups` mapper, add it under Verwaltung > Anmeldung with the redirect URI shown there,
  press "Verbindung testen" and "Testanmeldung", save, then sign out and sign in with the
  Keycloak button. Map a group to "Admin" with "IdP entscheidet" and check that the role is
  locked in Mitglieder; turn password sign-in off with yourself as break-glass admin and check
  that /anmelden/lokal still signs you in and the audit log lists it.
- LDAP: on a Windows Server domain controller (or a test domain), add the directory under
  Verwaltung > Anmeldung with `ldaps://<dc>:636`, a service account and the base DN of the users,
  press "Verbindung testen" with a test person and check that their groups are listed; save, map
  a group to "Bearbeiter", sign out and sign in with `DOMAIN\name` and the domain password,
  and check the role in Mitglieder. Disable that person in "Active Directory Users and Computers",
  press "Jetzt abgleichen" and check that the account is locked and listed under the sync.
- Service accounts: create one with the role Viewer, create a token for it, and in PowerShell run
  `Invoke-RestMethod -Headers @{ Authorization = "Bearer <token>" } https://<server>/api/orgs/<orgId>/dashboards`;
  check that the dashboards are listed. Revoke the token and check that the same call answers 401
  and that the audit log shows the refusal.
- Mail server: in Settings > Email set up a mail server you can reach from Windows (for example
  an Exchange or Microsoft 365 SMTP relay with STARTTLS on port 587), send a test mail to yourself
  and check that it arrives with umlauts intact and that the page shows the TLS version; save.
  Enter a wrong password and send a test mail: the error appears at Password, and Save stays
  unavailable.
- Invitation by mail: with `server.public_url` set, invite an address you can read; open the
  link in another browser, set name and password, and check that Start opens in the
  organization. Open the link again: it says the invitation was accepted already.
- Without a mail server: remove it, invite again and check that the link dialog appears and that
  "Copy link" in Open invitations copies the same link. Accept it, then set up the mail server
  again and confirm the address under Profile.
- Password reset: on the sign-in page choose Forgot password?, request a link for your account
  and for an unknown address (same answer), open the mail's link, set a new password and check
  that the other browser was signed out.
- `kalzit secrets rotate` with Kalzit stopped, then start: the test mail still signs in, and Copy
  link of a pending invitation without mail still works.
