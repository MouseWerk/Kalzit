# Kalzit 0.5.2

A security release: an organization's sign-in rules apply to every member again, linking an
account by its email address is safer, and requests through the outbound proxy can no longer be
led elsewhere.

## Improved

- Admins: an organization's sign-in rules apply to every member again, also to members you added
  directly and to all memberships from before 0.5.1. When the organization requires a second
  factor, a member without one sees "This organization requires a second factor" with "Set up
  now" instead of the organization's pages. When the organization turned password sign-in off, a
  member signed in with a password is asked to sign in through the organization's provider. Their
  other organizations, their profile, the second factor setup, leaving the organization and
  signing out stay available. This applies to server admins inside the organization too; the
  break-glass admin still gets in.
- After the update, admins and members may be asked to sign in again once: in an organization
  with password sign-in turned off, and in one that requires a second factor when your provider's
  second factor is what you rely on. Sessions from before the update count as signed in with a
  password and without a provider's second factor.
- Turning password sign-in off for an organization now needs a sign-in provider that leads into
  it, and you must be signed in through a provider or directory yourself, not with a password. A second factor rule that would
  shut you out asks you to set up your own second factor first.
- Server admins can put an organization's sign-in rules back to the server's from
  Verwaltung > Organisationen ("Anmelderegeln zurücksetzen"), after confirming their own second
  factor, when nobody can get into the organization any more.
- Members who joined by their own choice (invitation, creator, SCIM, a provider's group mapping)
  meet the rules at the sign-in, as before.
- The member list and the security overview count everyone who must still set up a second factor
  again, however they joined.
- "Add member" says "invite this person instead" for every existing account that cannot be added
  directly, without saying whether it belongs to another organization. SCIM refuses such an
  account with a neutral reason as well.
- The Windows installer opens the setup page only for a valid port, and over HTTPS when HTTPS was
  chosen as the listener.

## Fixed

- A sign-in provider no longer takes over an account by its email address when that account has
  no password and no second factor and signs in through another provider or a directory. The
  sign-in page says to sign in the way you usually do. An account an organization's SCIM made is
  linked at once only through a provider whose group mapping leads into that organization.
- Plain-http requests through the outbound proxy (organization AI providers, the plugin catalog,
  update and certificate sources) always go to the address Kalzit checked, so a name that changes
  its answer in between cannot lead the proxy to another address. A proxy that allows targets by
  domain name sees the address instead; allow them by address or use HTTPS.
- The outbound proxy can no longer be set to Kalzit's own address or to the server of its own
  database.

## Checklist for Windows (manual)

- Second factor rule for all members: in an organization with a member you added directly and no
  second factor, set Einstellungen > Organisation > "Zweiter Faktor Pflicht" to "Für alle". Sign in
  as that member and check that the page "Diese Organisation verlangt einen zweiten Faktor"
  appears, that "Jetzt einrichten" opens the second factor setup, and that the organization opens
  normally once the factor is set up.
- In the same state, check that another organization of that member, Einstellungen > Profil,
  "Organisation verlassen" and signing out all still work.
- Password sign-in off: turn password sign-in off for an organization with an OpenID Connect
  provider set up. Sign in with a password as a member and check that the page asks to sign in
  through the provider, and that "Über den Anbieter anmelden" leads to the sign-in page and back
  into the organization after signing in through the provider.
- Overview: check that the second factor overview under Einstellungen > Anmeldung and the member
  list count every member without a second factor of an organization that requires one.
- Add member: try to add an account that belongs to another organization and check that the
  dialog says to invite the person and does not mention the other organization.
- Installer: install the MSI with HTTPS (self-signed) chosen and "Open setup in the browser"
  ticked; check that the browser opens `https://localhost:<HTTPS port>/setup`. Install again with
  HTTPS off and check that `http://localhost:<port>/setup` opens.
- Lockout protection: as an organization admin signed in with a password, try to turn password
  sign-in off for the organization and check that it is refused with a hint to sign in through the
  provider first. Without a second factor of your own, try "Zweiter Faktor Pflicht" "Für alle" and
  check that it asks you to set one up first.
- Recovery: as a server admin with a second factor, open Verwaltung > Organisationen, choose
  "Anmelderegeln zurücksetzen" for an organization, confirm your second factor, and check that its
  rules show "Wie Server" again.
- Outbound proxy: set Einstellungen > Netzwerk, HTTPS und Proxy > "Ausgehender Proxy" to
  `http://localhost:3000` (Kalzit's own port) and check that it is refused with a clear message.
