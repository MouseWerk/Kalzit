# Kalzit 0.3.0

## Improved

- New sign-in and setup pages: one centred column on a calm backdrop, a slim bar on top with
  language, theme and help, and the copper only on the one main button. The light that drifts
  over the backdrop stands still when the system asks for reduced motion, and phones and the high
  contrast theme have none.
- Sign in: after too many failed attempts the page says how long to wait and the button counts
  down until you can try again. "Forgot password?" explains who can reset it, and a session that
  ended while you worked is named as such before you sign in again.
- Setup has four steps: the setup code is checked on its own step, then your account, then the
  organization with its defaults (language, theme, time zone), and a last page with the next
  steps. Back keeps everything you entered.
- "Where do I find the code?" on the setup page shows the way for each kind of installation
  (file, server log, Docker, fixed code), the one that fits the server first, with the default
  paths for Windows and Linux to copy.
- The setup page tells a code from before a restart of the server from a wrong one, and says when
  Kalzit is already set up.
- Sample data: a small, read-only SQLite database with orders, products, customers and regions
  ships with Kalzit; "Explore with sample data" at the end of setup adds it in one click and
  opens Explore on it. It can be removed like any data source.
- Help on the sign-in and setup pages opens the getting started and installation guides, which
  now ship with Kalzit and can be read without an account.
- Graph steps in Explore and in panels: count nodes per label and edges per type, the degree
  distribution, the top N nodes by degree, shared neighbours (such as customers who bought the
  same products), the degree as a node property, a filtered subgraph and "Turn into a table"; Neo4j
  and Memgraph run them in the database where they can, and each
  step shows where it runs and how it changes the shape.
- Variables work across result shapes: a click on a document in the document explorer or card,
  or on a table row, sets a dashboard variable, as a click on a graph node already did, and Cypher
  and GSQL panels follow it.
- Query variables can take their values from graph nodes, relationships or document fields.
- Graph panels have a details sheet for the selected node: labels, typed properties, edges and its
  neighbours by edge type, with Load neighbours and Set $variable.
- The explorer shows its steps: go back to any step, cancel a step still loading, undo with
  Ctrl+Z, and choose the number of neighbours, edge types and direction of the next step; Load N
  more continues with a node's next neighbours.
- Select several nodes with Shift+click, show only the selection, and set a multi-value variable
  to the selected nodes' values.
- Pin nodes so they stay when explorer steps are taken back; your pins and selection are kept for
  you per dashboard panel.
- Open an exploration as a Cypher query in Explore.
- The network panel has a legend that hides labels, and a layout switch for the view.
- New graph panel options: a color per label, color by a property, node size range, arrows and
  edge type labels, which labels show, and what a click on a node does.
- A hierarchy too large to lay out offers the network instead; paths fold after the first and can
  be shown as a table, with edge properties.
- TigerGraph: Test connection warns when REST++ runs without authentication, which lets anyone who
  reaches it run every installed query, and says how to turn it on; the data source page keeps the
  warning in view. Saving stays possible.
- TigerGraph: approved installed queries get their parameters and types from TigerGraph, so the
  query editor lists them and dashboard variables fill them, as in written GSQL; a value of the
  wrong type is refused before it is sent.
- TigerGraph: the installed-query picker lists the graph's queries for a user with only the
  queryreader role.

## Fixed

- A click on a drawn graph node no longer leaves a WebGL error in the browser console on every
  frame.
- A sign-in, setup or connection test that hit a limit now answers how long to wait, instead of
  only "wait a few minutes".
- A dashboard variable written into GSQL code as `$name` now says to declare a query parameter.
- TigerGraph: a user with only the queryreader role of TigerGraph 4.2 is accepted; it was refused
  as one that may write.
- TigerGraph: parameter values with spaces arrive as written; installed queries received a space
  as a plus sign.
- TigerGraph: an approved installed query that changes data is refused.
- TigerGraph: an expired login token is renewed instead of failing the query.

## Checklist for Windows (manual)

- First setup on Windows: start a fresh server, open it and check that the setup page shows
  "Where do I find the code?" with the File tab; copy the Windows path with the copy button, open
  the file and enter the code. Restart the server, enter the old code and check that the page
  says it is no longer valid; enter the new one and finish setup.
- Sample data on Windows: on the last setup step press "Explore with sample data", check that
  Explore opens on "Sample data" and that `SELECT * FROM orders LIMIT 10` returns rows; check that
  the file lies in `samples` in the data directory; delete the source and add it again from setup
  or check that another SQLite path in the data directory is still refused.
- Sign-in limit on Windows: enter a wrong password until the page says to wait, check that the
  button counts down and that "You can sign in again." appears at the end.
- Help on Windows: sign out, press Help in the top bar and check that the getting started page
  opens without signing in, and that its link to Installation stays inside Kalzit.
- Graph sources on Windows (the automated browser tests run Neo4j and Memgraph on Linux only): add
  a Neo4j source, run a Cypher query that returns nodes and relationships in Explore and check
  that the result shows as a **Network** with its node and edge count; switch to **Hierarchy** for
  a tree of relationships and to **Paths** for a `shortestPath` query and check the path reads as
  node, relationship, node. On a dashboard, lower a network panel's node limit below the result
  and check the note about the limit and **Show as table**; turn on explorer mode, load a node's
  neighbours, check that no more than the set number arrive and that **Undo** removes them; let a
  click on a node set a text variable and check that a panel using it follows. Repeat the Explore
  query against a Memgraph source.
- Graph interaction on Windows: on a Neo4j network panel, click a drawn node and check that its
  details open; Shift+click a second node and use **Show only the selection**; pin a node, load
  neighbours with the explorer, take the step back and check the pinned node stays; reload the
  page and check pins and selection are still there; use **Open as a query in Explore** and check
  the query opens unrun.
- Graph steps on Windows: in Explore, run a Neo4j query that returns customers, purchases and
  products, add "Shared neighbours" and check "Runs in Neo4j (Cypher)" and the pairs in the
  preview; add "Group" after it; add the panel to a dashboard and check that a viewer sees the
  same table.
- On a dashboard with a MongoDB document explorer that sets a variable and a Neo4j panel that
  uses it, click a document and check that the Neo4j panel shows the matching data.
- TigerGraph from a Windows server (the nightly job runs TigerGraph on Linux only): add a source
  with a queryreader user, check that Test connection passes, run an interpreted query in Explore
  and an approved installed query with a parameter that contains a space.
