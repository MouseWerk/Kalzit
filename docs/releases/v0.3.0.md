# Kalzit 0.3.0

## Improved

- Variables work across result shapes: a click on a document in the document explorer or card,
  or on a table row, sets a dashboard variable, as a click on a graph node already did, and Cypher
  and GSQL panels follow it.
- Query variables can take their values from graph nodes, relationships or document fields.
- TigerGraph: Test connection warns when REST++ runs without authentication, which lets anyone who
  reaches it run every installed query, and says how to turn it on; the data source page keeps the
  warning in view. Saving stays possible.
- TigerGraph: approved installed queries get their parameters and types from TigerGraph, so the
  query editor lists them and dashboard variables fill them, as in written GSQL; a value of the
  wrong type is refused before it is sent.
- TigerGraph: the installed-query picker lists the graph's queries for a user with only the
  queryreader role.

## Fixed

- A dashboard variable written into GSQL code as `$name` now says to declare a query parameter.
- TigerGraph: a user with only the queryreader role of TigerGraph 4.2 is accepted; it was refused
  as one that may write.
- TigerGraph: parameter values with spaces arrive as written; installed queries received a space
  as a plus sign.
- TigerGraph: an approved installed query that changes data is refused.
- TigerGraph: an expired login token is renewed instead of failing the query.

## Checklist for Windows (manual)

- Graph sources on Windows (the automated browser tests run Neo4j and Memgraph on Linux only): add
  a Neo4j source, run a Cypher query that returns nodes and relationships in Explore and check
  that the result shows as a **Network** with its node and edge count; switch to **Hierarchy** for
  a tree of relationships and to **Paths** for a `shortestPath` query and check the path reads as
  node, relationship, node. On a dashboard, lower a network panel's node limit below the result
  and check the note about the limit and **Show as table**; turn on explorer mode, load a node's
  neighbours, check that no more than the set number arrive and that **Undo** removes them; let a
  click on a node set a text variable and check that a panel using it follows. Repeat the Explore
  query against a Memgraph source.
- On a dashboard with a MongoDB document explorer that sets a variable and a Neo4j panel that
  uses it, click a document and check that the Neo4j panel shows the matching data.
- TigerGraph from a Windows server (the nightly job runs TigerGraph on Linux only): add a source
  with a queryreader user, check that Test connection passes, run an interpreted query in Explore
  and an approved installed query with a parameter that contains a space.
