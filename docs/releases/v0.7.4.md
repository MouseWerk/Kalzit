# Kalzit 0.7.4

0.7.4 brings public links and snapshots, provisioning as code with an import for Grafana
dashboards, scheduled reports by mail, traces as a shape of their own, many new data sources, and
server settings for CORS, self-registration and backups, together with app plugins and SDKs.

## Improved

- Public links: show a dashboard live to people without an account, with a required expiry, a
  window of time visitors may pick from, fixed variable values and a view count. The queries run
  with the creator's current rights; a link pauses while those rights, the creator's membership or
  the switch are missing, and revoking ends it for good. Off until a server admin turns it on; an
  organization can turn it off for itself. Visitors get only what each panel shows: its steps run
  on the server, and hidden queries and unused graph properties stay there. See
  [Sharing](../guide/sharing.md).
- Snapshots: freeze a dashboard's panel results for one time range, internal for the organization
  or public by link, with a size limit and an expiry.
- New permission `dashboards:public` for public links and snapshots, given to admins and owners
  and available for custom roles. Changing a dashboard with live public links, or a library panel
  or saved analysis it shows, needs it too, and the error names those links; only signed-in people
  publish, never API tokens.
- Share dialog on every dashboard, behind the Share button: the address for people in the
  organization (with or without the time range and the variables, or for one panel), public links
  with expiry and time window, and snapshots for the organization or in public. Existing links and
  snapshots of the dashboard are listed there, with their expiry to change and a revoke that asks
  first. Where public sharing is not available, the dialog says why: the server's switch, the
  organization's, or the missing permission `dashboards:public`.
- In the share dialog, the address of a new public link is labelled "Address of the public link",
  so screen readers no longer announce it with the same name as its tab.
- Pages for visitors without an account: the shared dashboard without navigation, the time range
  to pick inside the link's window, the fixed variable values readable, and no query text, data
  source names or error texts of a source. A public snapshot shows its frozen range. Every address
  that does not work shows the same "This link is not available."
- Snapshots in the organization open inside the app, with who froze them, until when they stay and
  the way back to the live dashboard.
- Administration > Shares lists every public link and snapshot of the organization with its
  status and reason, expiry and views; Settings > My shares lists your own across your
  organizations. The sharing settings have sections of their own: Sharing (server) and Sharing in
  the organization.
- Provisioning as code: dashboards, data sources, custom roles and alert rules as YAML or JSON
  files in a folder, planned, applied and exported with `kalzit provision plan`, `apply` and
  `export` through the API of a running server with a service account's token. A provisioning set
  belongs to one organization and owns its resources; an apply is all or nothing, removes
  resources only with `--prune`, and reports drift. Secrets stay out of the files: they name
  environment variables or keep what Kalzit stores. New permissions `provisioning:read` and
  `provisioning:write` for organization admins.
- Dashboards, data sources, alert rules and roles that a provisioning set manages are marked
  "Managed by files" for people who may read the sets: the badge opens the set, the file and the
  last apply, the settings are read-only, and Edit on a dashboard stays in place, locked, with the
  reason. In an emergency, organization admins unlock one resource there until the next apply,
  after a question that says what that apply will do. A refused change names the set and the file
  to change instead.
- Administration > Provisioning shows the sets of the organization, the managed resources with
  their files, the last applies from the audit log and where the server differs from the files
  (unlocked, changed, deleted). While nothing comes from files, it shows the first commands to
  copy.
- Import of Grafana dashboards from their JSON, under Dashboards > Import from Grafana,
  with `kalzit provision import-grafana` or through the API: panels, queries, variables, rows,
  annotations, links and time settings are converted where Kalzit has a counterpart. In the
  interface, you upload or paste the JSON, map each data source of the file to one of Kalzit's
  (proposed by name and kind) or leave it out, and read the report of what is converted,
  approximated and skipped before anything is created. The new dashboard opens with a line that
  leads to the report, which stays with the dashboard. Nothing is queried or contacted during the
  import.
- Reports: a dashboard, all of its panels or some, sent by mail on a schedule (daily, weekly,
  monthly or a cron expression, in a time zone) as a PDF file, CSV files or both, with its own
  time range and fixed variable values. Kalzit draws the PDF itself on the server, without a
  browser: time series, bars, stat values and tables, documents as a tree and graphs as a static
  layout, each in its own shape; panels it cannot draw show the reason. CSV files hold table
  results, several of them in a zip file, and go only to recipients allowed to export data. See
  [Reports](../guide/reports.md).
- A report runs with the current rights of the person who created it and is suspended while one
  is missing; recipients must be able to read the dashboard. A failed run sends nothing to the
  recipients, is tried once more after five minutes and then tells the creator. Addresses outside
  the organization are off by default; organization admins may allow them, also limited to mail
  domains, and their mails have a one-click unsubscribe. An organization may turn reports off for
  itself. New permissions `reports:read` and `reports:write` for editors and up; new server
  settings to turn reports off and to limit reports, runs per hour, recipients (20) and the size
  of a mail (10 MB).
- "Reports" in the main navigation lists the reports of the organization with what they send,
  their schedule, format, recipients, next and last run and the person whose rights they run
  with; filters show your own reports and those with problems. Suspended and paused reports say
  so in words, and a suspended one names its reason.
- The report editor: dashboard or selected panels, time range and fixed variable values, a daily,
  weekly or monthly schedule or a cron expression with its time zone and the next runs, recipients
  by name or address, PDF, CSV or both, and the language. Errors show at their field, a refused
  recipient at the person the server names.
- A preview draws the draft as PDF on the server, with the data of now and your own rights, and
  sends nothing; "Send now" asks first, since it goes to every recipient.
- Each report lists its runs with trigger, duration, delivered recipients, size and the result with
  its reason.
- "Create report…" in a dashboard's menu starts a report with the time range and variable values
  chosen there, and the menu leads to the reports the dashboard already has.
- Without a mail server the report pages say so and lead server admins to Administration > Mail.
- Pausing a report always works, also when a panel has left its dashboard or a right is missing;
  resuming checks the report first and says what stands in the way.
- Traces are a shape of their own next to tables, documents and graphs: spans with their service,
  operation, kind, start, duration, status, attributes, events, links, resource and scope. A trace
  with more than 10,000 spans keeps exactly 10,000, its root spans first, then its error spans,
  then the earliest others, and says how many it kept. Steps work on it: filter spans, the
  critical path, a span table, a trace table, the service map and the span tree. For now they are
  set in a panel's steps through the API; the trace screens with their own editors follow. See
  [Traces](../guide/traces.md).
- New data sources Tempo and Jaeger (its query service). A search needs no query language:
  service, operation, tags, duration and status; it lists the traces found as a table, and for
  Tempo shows the TraceQL Kalzit wrote for it. A trace id shows the whole trace. Services,
  operations and tag values come as tables too, for dashboard variables. Both sources only read:
  Kalzit never reaches their span receivers. See [Data sources](../guide/data-sources.md#tempo).
- Traces export as OTLP JSON. An alert rule on a trace source reduces a span table or a trace
  table and says so when the step is missing. AI summaries and the AI chat also read traces after
  steps that keep a trace, such as the critical path.
- New data source ArangoDB (AQL): traversals and edges arrive as graphs, other results as
  documents. Kalzit refuses database users that may write, checks every query and lets ArangoDB
  parse it before it runs, so writing queries are refused.
- New data source Gremlin for graph databases behind Apache TinkerPop Gremlin Server: traversals
  are checked and sent as bytecode under the server's read-only strategy, never as scripts;
  vertices, edges and paths arrive as graphs.
- New data source Couchbase (SQL++): only SELECT statements run, always as read-only requests, and
  database users with roles beyond reading are refused; results arrive as documents.
- ArangoDB, Gremlin and Couchbase have Test connection, schema browsing, query editors with
  highlighting, Explore starters and a cheat sheet, and a guide page each.
- New data source Graphite (graphite-web, carbonapi): targets with Graphite's functions over the
  render API, each series a line with its tags as labels, and metric names suggested in the
  editor. See [Data sources](../guide/data-sources.md#graphite).
- New data source Redis (also Valkey, and with Redis Stack or Redis 8 JSON, search and time
  series): one command that reads per query, as in `redis-cli`; values, hashes, sorted sets,
  `INFO` and time series become tables, stream entries, JSON documents and search hits become
  documents. Only commands that read run; writes, scripts, blocking reads and `KEYS` are refused.
  The schema lists keys found with `SCAN`, with their types. See
  [Data sources](../guide/data-sources.md#redis).
- New data source Oracle Database, without an Oracle Client to install: SQL with the macros and
  variables as bound values, every query in a read-only transaction, and the tables and views of
  the login in the schema. See [Data sources](../guide/data-sources.md#oracle).
- ClickHouse can also be queried over its native protocol (port 9000, or 9440 with TLS), with the
  same read-only checks, parameters and types as over HTTP; a query cut off at a limit is
  cancelled on the server.
- Explore offers starters, a cheat sheet and error hints for Graphite, Redis and Oracle, and the
  query guide has sections for them
  ([Query languages](../guide/query-languages.md#graphite)).
- New data sources for data warehouses: Google BigQuery (service account key or workload identity
  federation), Snowflake (key-pair authentication) and Databricks SQL (personal access token or
  OAuth machine-to-machine), with Test connection, schema browsing and Explore starters.
- BigQuery estimates every query in a dry run first, shows the estimated bytes with the result
  and refuses a query above the source's maximum bytes billed.
- Queries in the three warehouses are read-only, are cancelled in the warehouse when Kalzit stops
  waiting for them, and are kept in the query cache by default to save costs.
- CORS: administrators can let pages of chosen origins call Kalzit's API from the browser (exact
  origins, or all subdomains of a domain); off by default, with or without the session cookie,
  lockable in `kalzit.toml`.
- Self-registration: people with an address of an allowed domain can create an account
  themselves. The address is confirmed by mail, an admin approves each account by default, new
  accounts join a chosen organization as viewer or editor, and sign-ups are limited per address,
  email and day.
- Scheduled backups: Kalzit backs up its database, `acme/`, `plugins/` and `kalzit.toml` on a
  schedule into an allowed folder or an S3-compatible bucket, encrypted with the secrets key,
  keeps the newest 14 and lists every run. `kalzit backup restore` puts a backup back.
- App plugins: plugins can bring pages of their own, which read dashboards and saved analyses with
  your rights and keep their own data. Organization admins can block an app or allow it only from
  a role up.
- SDKs for TypeScript (Node and browsers) and Go: typed clients for service account tokens,
  dashboards, data sources, queries in their native shapes and alerts.
- Sign in, the second step, password and invitation links and setup: on wide screens the form
  stands on the left and a panel on the right carries the backdrop. The admin's sign-in notice is
  now a card of its own in that panel, level with the heading (above the form on phones), instead
  of a small grey box. A notice longer than the window is shown in full: the page scrolls to its
  end.
- Settings > Appearance and brand: "Product line before sign-in" turns off the line about Kalzit
  in that panel. A server with its own product name or logo never shows the line.
- Every release now also carries the container image as a file, one per processor
  (`kalzit-<version>-image-linux-amd64.tar.gz` and `-linux-arm64.tar.gz`), for everyone without
  access to ghcr.io and for servers that cannot reach it: `docker load` and `podman load` read it.
  A checksum file signed with cosign by the release workflow (`kalzit-<version>-image-SHA256SUMS`
  and its `.sigstore.json`) ties each archive to the release; its SHA-256 alone only shows that
  the download is complete. With access to ghcr.io, the archive's config digest can also be
  compared with the signed image
  ([Installation](../guide/installation.md#loading-the-image-from-the-release)).

## Fixed

- Alerting: two changes of the same rule at the same time no longer skip ending its alerts when
  it moves to another data source, and pausing, resuming, deleting or changing a rule checks the
  data source it has at that moment.
- Alerting: Slack notifications with a long dotted title no longer exceed Slack's header limit.
- Alerting: alert groups from 0.7.2 that are given their data source no longer risk a database
  deadlock on PostgreSQL, and their waiting notifications keep the data source of their alerts.
- Alerting: the cache of notification policies is limited by the memory its patterns may take.
- Hover tooltips of charts lie above everything now: the panel's edge no longer cuts them off,
  and neighbouring panels, sticky table headings, the dashboard toolbar and the top bar no longer
  cover them. They follow the pointer and flip or shift at the window's edges, so they stay fully
  visible.
- With a shared cursor that shows values, the tooltips of the other panels stay inside their own
  panel: they no longer cover the toolbar or a neighbouring panel, and a panel with too little
  room on screen shows only its cursor line.
- The tooltips of icon buttons and of the icon rail lie above the page as well and stay inside
  the window.
- A tooltip that opens while a dashboard's panels are still taking their size no longer causes a
  "ResizeObserver loop" error in the browser's console.
- "Export as image" gives a clean picture of the panel: square, without the card's border line
  and rounded corners inside it, filled with the panel's colour to the edges.
- The image of a panel set to "Transparent" is a transparent PNG now; the page's colour is no
  longer painted behind it.
- Sign in: the name of a sign-in provider that is too long for its button wraps inside the card.
- A row or toolbar menu opened right after the page scrolled to its button no longer closes again
  at once; it still closes when a scroll moves its button.
- A stopping server lets running live updates finish their current query before it closes the
  databases, so the files of SQLite data sources are always closed when the stop completes.

## Checklist for Windows (manual)

- Add an Oracle source (for example the `gvenzl/oracle-free` container) on a Windows server
  without an Oracle Client installed: Test connection shows the Oracle version, and a query
  returns rows.
- Add a Redis source and a ClickHouse (native protocol) source; Test connection succeeds, and
  `SET` in a Redis query is refused because only commands that read run.
- Save a local backup target below an allowed folder, run a backup through the API and check that
  the file appears there.
- Stop the service, run `kalzit.exe backup restore <file> --yes` from an elevated prompt, start
  the service and sign in.
