# Kalzit 0.5.4

A security release: the reason why an address could not be added is only in the server's audit
log, the password confirmation for a first second factor is asked for only when it is needed, and
audit log exports have limits.

## Improved

- An organization's audit log says only that a member could not be added or that a SCIM request
  was refused, not why. Why (no account, a member of another organization, an unconfirmed address)
  is in the server's audit log, for server admins, as "Mitglied nicht hinzugefügt: Grund" or
  "SCIM-Anfrage abgelehnt: Grund". Older entries no longer show the reason in an organization's
  log or export either.
- "Add member" takes the same time for an address without an account as for one that cannot be
  added directly.
- If you sign in through an identity provider or directory and also have a password, you can set
  up your first second factor within five minutes of that sign-in without entering the password.
- Wrong passwords entered in a signed-in browser (when changing the password or confirming it for
  a second factor) no longer block your sign-in on a new device; they only pause further attempts
  in that browser.
- An account that has a second factor is no longer asked for its password to confirm a change; it
  confirms with its second factor.
- Audit log filters can be at most 256 characters long. An audit log export stops after five
  minutes with a clear message, and a refused export (too many events, too large, too slow) is
  recorded as "Audit-Log-Export abgelehnt".
- Before password sign-in is turned off, an admin who may change the settings but not see the
  members sees how many owners and admins would be locked out, without their names.
- The HTTPS guide says clearly that a reverse proxy must set and overwrite `X-Forwarded-Proto` on
  every request.

## Fixed

- Two first second factors set up at the same moment in two browsers could both count as the
  first. The second one now needs a confirmation with the first.
- Panel images only take files from Kalzit itself and follow no redirect, and an image without an
  address is left out.

## Checklist for Windows (manual)

- Add member: as an organization admin who is not a server admin, add an address no account has.
  Open Verwaltung > Audit-Log of the organization and check that "Mitglied nicht hinzugefügt" shows
  no reason, also in the CSV export. As a server admin, open the server's audit log and check that
  "Mitglied nicht hinzugefügt: Grund" names the organization and the reason.
- First second factor after a provider sign-in: with an account that has a password and signs in
  through a provider, sign in through the provider, open Einstellungen > Anmeldung und Sicherheit
  and choose "Einrichten" for the app. Check that no password is asked for and the setup goes
  through. Wait more than five minutes in another such session and check that the password is
  asked for.
- Wrong passwords: in a signed-in browser, enter a wrong current password under Einstellungen >
  Profil > "Passwort ändern" ten times. Check that a sign-in with the right password in a private
  window still works.
- Audit export: as a server admin, export the server's audit log as CSV and JSON and check that
  both files open. Enter an action filter longer than 256 characters and check that the export is
  refused with a message.
- Password sign-in off: with a custom role that holds `settings:write` but not `users:read`, set
  Einstellungen > Organisation > "Anmeldung mit Passwort" to "Aus" while an owner has only a
  password. Check that the dialog names the number of owners and admins and no names.
