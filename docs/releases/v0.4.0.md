# Kalzit 0.4.0

## Improved

- AI, off until a server administrator turns it on: under Settings > AI (Verwaltung > KI) connect
  a provider (any OpenAI-compatible server such as Ollama, LiteLLM or OpenAI, or Anthropic), test
  it and turn "AI functions" on.
- Without a tested provider the AI switch stays off, and while AI is off no AI button or hint
  appears anywhere.
- The AI page shows each provider with its address and whether data leaves your own network
  (set per provider, or judged from its address), the usage per day and organization in calls
  and tokens, the limits per person and organization, and "Which data leaves the server" with a
  paragraph of your own.
- With several providers, "Which provider for what" chooses one for explain and draft, one for
  summaries and one for Ask.
- Organizations can turn AI off for their members, connect a provider of their own when the
  server allows it, lower the limits and keep chats for a shorter time (Settings > AI of the
  organization).
- Data sources have an AI part: "AI may read" (off by default) decides whether AI sees the
  source's schema and results. The data source list marks opened sources.
- "Excluded fields" of a data source leaves the values of named fields out before anything is
  sent. This works by name, so data that must never reach a provider stays in a source closed to
  AI.
- Before the first AI call, everyone sees once per provider which data goes where.
- Explore: "Explain" explains the query in the editor and "Draft" writes a query from a
  description. A draft never runs by itself: "Apply" puts it into the editor, where running it is
  checked like any query.
- "Summarize" in Explore and in a panel's menu summarizes a result of sources opened to AI and
  says what was sent; viewers can summarize the panels they see.
- Answers appear while they are written, can be stopped with Stop or Escape, and say when a limit
  is reached or a source is not open to AI.
- Ask (Fragen, beta): ask questions about your data in plain words. The assistant looks up the
  sources, reads their schema and runs read-only queries with your rights or the panels of
  dashboards you may read.
- Ask shows every step with its query and result, the tokens it used and "Open in Explore". You
  choose which sources it may use; only sources open to AI can be chosen.
- Ask can take a dashboard as context ("Dashboard as context", or "Open in Ask" in a panel's
  menu), and a summary offers "Continue in Ask".
- Under an answer in Ask, "Save as panel", "Add to dashboard" and "Adjust query" take its query
  on; a result over time switches between table and time series. The side pane shows the
  provider, its endpoint, its last test and whether data leaves your network.
- Chats are visible to you only, listed under Ask > History with the days until they are deleted
  (30 days by default, shorter if your organization says so), and can be deleted one by one or
  all at once.
- Every AI call and every step of the assistant is in the audit log, without your question, the
  answer or any result.
- Plugins: server administrators install data source and panel plugins under Settings > Plugins
  (Verwaltung > Plugins), approve the network targets a plugin declares, and turn it on or off,
  restart or remove it.
- A data source plugin's kind appears in "Add data source" in a group of its own, with the labels
  of its manifest; Explore and the panel editor take its query as JSON.
- Every package is checked before anything in it runs: a valid signature from a trusted key, only
  the files its manifest lists, the platform and the Kalzit version.
- "Install from file" shows the checks step by step and the network targets to grant; a refused
  package names the step and the reason, and an untrusted publisher leads straight to comparing
  and adding its key.
- Unsigned plugins install only behind a switch that is off by default and asks for the server's
  name; while it is on, a band on every plugin page says so. A broken signature is always
  refused.
- Updates of a plugin stay with its publisher's key and never go back to an older version. An
  update that wants new network targets waits for approval while the installed version keeps
  running. Publishers can hand a plugin over to a new key.
- "Signature and trust" lists the trusted keys with their fingerprints. Adding a key shows the
  fingerprint to compare with the publisher's; removing one names the plugins it stops.
- Each plugin has its own page: its manifest, the granted targets, the process with its sandbox
  layers, its log, the data sources that use it in every organization, and when a crashed plugin
  starts again. The list of installed plugins filters for problems and waiting updates.
- Plugin processes start when they are first needed, are restarted with growing waits after a
  crash, and stop after repeated failures until an administrator restarts them. A crashing plugin
  fails only the queries of its own kind.
- Plugins run in a sandbox: on Windows with a restricted token in a job object and an
  AppContainer without network, on Linux with Landlock, seccomp and namespaces where the system
  offers them.
- On Linux plugins need Landlock unless an administrator allows them without it; without
  Landlock a plugin could read Kalzit's files.
- On Linux a plugin's network stays closed through the seccomp filter or a network namespace;
  only if plugins are allowed without Landlock and the host offers neither, a plugin starts with an
  unlimited network and its page warns about it.
- Plugins have no network of their own: they reach only the targets their manifest declares, and
  only through Kalzit, which checks every connection against the data source's settings and the
  target rules.
- Kalzit's connector for plugins never connects to Kalzit itself or to cloud metadata addresses.
  Refused connections appear in the plugin's log and the audit log.
- On Windows plugins do not start while one of Kalzit's files with secrets (`kalzit.toml` with a
  password, the TLS key) is readable by them; the plugin's page names the file.
- Organization administrators can block an installed plugin for their organization under
  Settings > Plugins of the organization.
- Panel plugins are visualizations in the panel editor like the built-in ones, marked as a plugin
  with their publisher, with options from their manifest.
- A panel plugin draws the panel's query results in a sealed-off frame without network and
  without access to Kalzit, your session or other panels. A link it wants to open opens only after
  you confirm; a panel that does not start shows an error with "Try again".
- Plugin catalog, off until a server administrator turns it on with the address of a signed list
  (Settings > Plugins > Catalog).
- The catalog lists data source and panel plugins with their publisher key, version and network
  targets, with a search; installing or updating one runs the same checks and approval as a file.
- Kalzit takes only catalog lists signed by Kalzit's key or a key you allowed for the catalog
  under "Signature and trust", never an older or expired one. Withdrawn versions are refused, and
  installed ones the list withdraws are named.
- Installing, approving, turning on and off, removing, blocking, every change of trust and every
  install from the catalog are recorded in the audit log.
- Two example plugins, signed with Kalzit's own key, install without adding a key: "CSV and JSON
  over HTTP" (`dev.kalzit.csv-http`) reads a CSV or JSON file from a URL into a table.
- "KPI tile" (`dev.kalzit.panel-kpi`) shows the latest value of a number field with a sparkline.
- Plugin authors write data source plugins in Rust with the Kalzit plugin SDK and package and
  sign them with the `kalzit-plugin` tool; the author guide walks through data source and panel
  plugins.
- Drop-down lists and on/off switches look the same in every browser and in light and dark.

## Fixed

- Test connection and the schema of a data source whose kind is not available answer
  "kind not available" instead of an internal error.
- The update page shows release note points that span several lines as one point.

## Checklist for Windows (manual)

- AI: run Ollama (or another OpenAI-compatible server) on the same machine, add it under
  Settings > AI with `http://localhost:11434/v1` and a pulled model, press "Test connection" and
  check that the answer and the time appear; turn "AI functions" on.
- Open a SQLite source to AI on its page ("AI may read"), add `email` to "Excluded fields", then
  in Explore run `SELECT * FROM customers LIMIT 5` on it, press "Summarize" and check that the
  notice appears once, that the summary streams in and that the note says how many rows were
  sent; press "Explain" and "Draft", apply a draft and check that Ctrl+Z takes it back.
- Stop a running answer with Escape and check that the audit log shows the call as cancelled,
  without any query text.
- Open Ask, choose the SQLite source, ask "How many customers are there?" and check that the steps
  (sources, schema, query) appear with the query and its result, that the answer names the number,
  and that "Open in Explore" opens the query in Explore without running it. Restart the Windows
  service and check that the chat is still listed under Ask > History; delete it there.
- With two providers, choose another one for Ask under Settings > AI, ask in Ask and check that
  the notice names that provider and that the side pane shows its endpoint and status.
- On a Windows service installation, install `dev.kalzit.csv-http` from the release assets with
  "Install from file" without adding a key: check that the steps, the publisher and the key id
  appear, grant the permissions with "Start after installing", create a source of its kind with
  the URL of a CSV file on the network, press "Test connection" and run a query; check that the
  columns and their types appear and that the plugin shows "Running".
- On the plugin's page check the log, "Used in" and the sandbox layers (restricted token, low
  integrity, job object, `app_container`, `network`); check in Task Manager that the plugin
  process runs under the service account and ends when the plugin is turned off and when the
  service stops. Set the source's URL to `http://169.254.169.254/` and check that saving is
  refused.
- Upload the same package with one file changed and check that it is refused before anything
  runs.
- Install a data source plugin signed with your own key: add the publisher key under "Signature
  and trust" (compare the fingerprint), install, approve and enable it, and run a query.
- Turn "Allow unsigned plugins" on (type the server's name), check the band on the plugin pages,
  and turn it off from the band.
- Install `dev.kalzit.panel-kpi` from the release assets, approve and enable it, add a panel with a
  SQLite query that returns a number column, choose "KPI tile" under Visualization and check in
  Edge and Firefox that the value and the sparkline appear and that its options (Field, Decimals,
  Label) change the tile. Block the plugin under Settings > Plugins of the organization and check
  that the panel says so.
- Plugin catalog: serve a signed catalog list and a signed package over HTTPS from another machine
  (or a mirror in the internal network), allow the signing key for the catalog under "Signature
  and trust", enter the list's address on the Catalog tab and turn the catalog on. Check that the
  list appears with "List signed by …", install a plugin from it, grant its permissions and run a
  query. Replace the list with an older signed one, press "Refresh now" and check that it is
  refused while the previous list stays; turn the catalog off and check with Resource Monitor that
  the service makes no further connection to the catalog host.
