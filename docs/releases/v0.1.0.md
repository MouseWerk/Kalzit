# Kalzit 0.1.0

## Improved

- Settings, About: the version and build of your server, the license (AGPL-3.0) with what it
  means for you, links to the source code, website and security policy, and a searchable list of
  the third-party licenses Kalzit ships with.
- First start: set up Kalzit in the browser with the one-time setup code from the data directory,
  creating the first organization and its owner.
- Sign in with email and password; on your account page, change your name and password and end
  your sessions.
- Organizations with members, teams and the roles owner, admin, editor and viewer, plus custom
  roles made of individual permissions, managed in the administration.
- Server settings and organization settings in the administration, showing where each value comes
  from (environment, configuration file or saved in Kalzit).
- An audit log of sign-ins and changes, kept for a configurable number of days.
- Server administrators manage user accounts and organizations.
- Deleting an annotation can be undone; undoing writes it again as a new entry, so the audit log
  shows it as added again.
- In the web interface and through the API: folders and dashboards with trash and version history,
  restricted folders, sharing with people, teams and roles, and read-only data sources for
  PostgreSQL, MySQL and MariaDB, SQL Server, SQLite and Prometheus with encrypted passwords.
- Without configuration, Kalzit keeps its data in a system folder: `%ProgramData%\Kalzit\data` on
  Windows and `/var/lib/kalzit` on Linux, never in the folder it was started from (for a Windows
  service, `C:\Windows\System32`). `paths.data_dir` in `kalzit.toml` or `KALZIT_PATHS_DATA_DIR`
  choose another place.
- Relative paths in `kalzit.toml` (data directory, certificate, key, SQLite database) are relative
  to the folder of the file, wherever Kalzit is started from.
- The data directory is created private: only the account Kalzit runs as and administrators can
  open it. Kalzit refuses to start when an existing data directory, or a file in it, is open to
  other accounts, and the message says how to fix it.
- Linux with systemd: run Kalzit as its own user with `StateDirectory=kalzit` and
  `StateDirectoryMode=0700` in the unit; without systemd, create the folder with
  `sudo install -d -o kalzit -m 0700 /var/lib/kalzit`.
- Windows: run the service as a virtual account (`NT SERVICE\Kalzit`) or as LocalSystem. Kalzit
  creates a missing `%ProgramData%\Kalzit` writable only by administrators; `kalzit.toml` and the
  folder are refused when other accounts could change them. If you ran Kalzit once as a normal
  user before installing the service, the service refuses the folder that user created and says
  how to fix it with `icacls`.
- Docker volumes and WSL drives (drvfs): the data directory must belong to the user Kalzit runs as,
  with mode 0700; otherwise Kalzit refuses to start (for drvfs, mount with `metadata` and set the
  owner and mode, or use a folder on the Linux file system).
- The built-in SQLite database lets reading go on while changes are saved. When it is briefly
  busy, the server says so and the browser tries again on its own.
- A SQLite database on a network drive is refused at start with a clear message; use PostgreSQL
  for shared storage or several Kalzit servers.
- The start log names the data directory and the database. The database address is shown with the
  password and all query values replaced by `***`, except harmless settings such as `sslmode`.
  When special characters in the password are not percent-encoded, Kalzit warns at start and shows
  only the scheme of the address, such as `postgres://***`.
- Backups: while Kalzit runs, use `VACUUM INTO` or the sqlite3 `.backup` command; with Kalzit
  stopped, copy `kalzit.db`, `kalzit.db-wal` and `kalzit.db-shm` together. Back up the key file
  too. To restore, copy the files back instead of moving them, and do not use tools that copy
  permissions (`robocopy /COPYALL`, `xcopy /O`).
- Closing the console window or shutting down Windows stops Kalzit cleanly.
- Dashboards: collapsible rows that you can reorder by dragging or with the arrow keys; panels
  and rows that repeat for each selected value of a variable that allows several values.
- Annotations on every time chart: write them with Ctrl+click, the A key or the panel's
  "Annotate" button, with text and tags; annotation queries add marks from a data source.
- Links under the dashboard title (to addresses or to dashboards with a tag) and data links in
  panel headers, with variables filled in; only web, mail and local addresses are allowed.
- Panels can have their own time range and a time shift, shown in their header.
- Kiosk mode, TV mode with controls that hide themselves, a single panel in full screen, and
  playlists that show dashboards one after another.
- Library panels: one panel shown by many dashboards, with a warning before a change reaches all
  of them.
- The dashboard model as JSON, checked by the server; export and import of dashboards with a
  confirmed mapping of data sources; copy a panel to another dashboard and "save as".
- Steps on query results, in the panel editor and in Explore: calculated fields with formulas
  (also across two joined queries, such as revenue per session), statistics (sum, mean, median,
  percentiles, standard deviation), trend line, moving average, correlation, comparison with the
  previous week, month or year, group and pivot. Each step can be moved, turned off and removed,
  with a preview after every step; the queries themselves stay as they are.
- Export a panel or an Explore result as CSV (semicolon and decimal comma in German, for Excel),
  Excel workbook or JSON, with the steps applied. Editors and up may export; viewers may not, and
  every export is in the audit log.
- Command palette (Ctrl+K, on macOS Cmd+K): find dashboards, folders, data sources,
  administration sections and recently opened dashboards by a few letters of their name, and
  run actions such as a new dashboard, Explore or the theme. It only lists what you may open.
- The start page greets you with the organization in numbers (dashboards, data sources,
  members and the changes of the last seven days, as far as you may see them) and shows your
  starred and recently opened dashboards as cards you can star or open for editing. Star a
  dashboard from its page or its card.
- The sidebar starts with a card for your organization that opens its settings, members and
  teams; Search sits in the navigation and also opens with /. The button that collapses the
  sidebar sits at the top left of the page, before the breadcrumbs (also Ctrl+B). A first-steps card (add a data
  source, create a dashboard, invite a colleague) ticks off what is done and can be hidden.
- Breadcrumbs on dashboards, folders, data sources and the administration.
- Press ? for the keyboard shortcuts of every area.
- Personal preferences on your account page: language, theme, time zone, start dashboard and
  first day of the week. They apply at once, can be undone and follow you to every browser. All
  times in Kalzit follow the chosen time zone: lists, tables, charts, time ranges such as "today"
  and the audit log's day filter. A language or theme you pick on the sign-in page becomes your
  preference when you sign in, unless you already have one.
- Saved, failed and undo messages appear in one place at the bottom of the window and are read
  out by screen readers.
- A stop gives open requests 10 s and then up to 5 s to close the database. With Docker, use
  `docker stop -t 20` or `docker run --stop-timeout 20` (in Compose `stop_grace_period: 20s`),
  since the default of 10 s can cut the clean stop short.
- Dashboards, Explore and lists use the whole width of the window; forms and settings keep a
  comfortable reading width. The interface uses calm graphite surfaces with white cards in the
  light theme, softer corners and a denser dashboard grid.
- Panel actions appear when you point at a panel or reach it with the keyboard, so a dashboard
  shows titles and data instead of rows of buttons; on touch screens they stay visible.
- Adding a data source shows each kind as a card with the product's logo and a short
  description; the list and the form show the same logo next to the kind.
- Visualizations: gauge, bar gauge, pie and donut, heatmap, histogram, state timeline, status
  history and text (Markdown with dashboard variables), next to time series, stat, bar chart and
  table. A picker shows each type with a small drawing and offers those that fit the query first.
- Field options for every panel: units per language (data sizes, rates, durations, currencies,
  SI units, temperatures, dates), decimals, min and max, thresholds, value mappings, a text for
  missing values, display names, colors and overrides per field; legends as list or table with
  last, min, max and mean, and tooltips for one series, all or none.
- Tables: column filters (text, or `>`, `<`, `=` and `!=` on numbers), pages, colored text or
  background, gauge cells and links per column.
- Patterns in overrides and value mappings use RE2 syntax (no lookaround or backreferences); a
  dashboard with another pattern is not saved, and the message names the panel.
- The network, hierarchy and path panels appear in the picker with a drawing and a short
  description, and their options are checked when a dashboard is saved, like those of every other
  panel.
- Units typed by hand in panels from before the field options stay a plain suffix after the value.
- Restoring an older dashboard version checks the options of every panel edited since that
  version; a version whose options today's rules refuse cannot be restored once that panel has
  changed. Dashboards from before keep opening, querying and saving while their panels are left
  as they are.
- The sign-in and setup pages have the graphite look of the app: on wide screens a quiet panel
  with the Kalzit mark, the product line and a drawing of the three result shapes stands next to
  the form. Password fields can show what you typed and warn when Caps Lock is on; setup groups
  its fields into three steps and rates a new password while you type it. Signing out is
  confirmed on the sign-in page, and too many failed sign-ins say how long to wait.
- Query editors for Elasticsearch and OpenSearch, CSV and JSON files and HTTP JSON, in Explore and
  in the panel editor. Search sources take an index picked from the cluster or typed as a pattern,
  a Lucene query or Query DSL with suggestions for the index's fields, ready-made aggregations,
  the number of hits and the time field; aggregations become a table. File sources show the file,
  how it is read and its columns. HTTP JSON sources take a path below the source's URL, query
  parameters and the path to the documents, with a preview of the request. A query the server
  would refuse says why before you run it.

- Editing and adding a panel happen on a page of their own, with an address you can reload or
  share (`.../panels/<id>/edit`, `.../panels/new`): the bar with Back, the time range, Refresh,
  Discard, Apply and Save dashboard; the preview on top with a table view; the queries and steps in
  tabs below; the options on the right in groups you can fold, the visualization first. Drag the
  separators or move them with the arrow keys; the editor remembers their place and whether the
  options are folded away. Back, Apply and Esc keep the change in the dashboard until you save it;
  Discard and the browser's back button leave the panel as it was, after asking when something
  changed. A new panel starts with an empty query and joins the dashboard only on Apply or Save.
  A reload of the tab keeps your unsaved changes; leaving the dashboard with unsaved changes asks
  first.
- Queries in the panel editor can be folded, duplicated and hidden; a hidden query stays with the
  panel but does not run.
- A panel's actions (its links, view alone, annotate, inspect, export, edit, duplicate, copy and
  remove) are in one menu behind a button in its title bar, so narrow panels keep a one-line
  title.
- Typing in the panel editor and dragging panels stay smooth on slow computers: a key redraws
  only the query you type in, and a dragged panel follows the pointer, shows where it will land
  and moves the others once you let go. Queries run on Ctrl+Enter, the run button or when you
  leave a changed query.
- A bar on top of every page shows where you are, with the search (/ or Ctrl+K), a New menu for
  dashboards, folders, imports and data sources, and Help with the keyboard shortcuts and the
  documentation; on a phone they are icon buttons. The bar stays at the top while a page scrolls,
  a dashboard's toolbar right below it, and jumps to a setting or a panel land below both.
- A dashboard's toolbar is one quiet row: the variables as a filter bar at its start; on the right
  the time range with its zone, refresh and share as split buttons, Edit and a More menu
  (settings, kiosk and TV mode, history, access, save as, delete). A column at the canvas' right
  edge groups the outline of rows and panels, showing and hiding the filters and annotations,
  sharing and export, kiosk, TV and full screen, the history and the dashboard's info; while
  editing it adds visualizations, rows, text and library panels. It is always shown on wide
  screens. On a phone the toolbar takes two rows of buttons and the More menu holds the column's
  actions.
- The time range moves back and forward by its own length and zooms out to twice its length,
  with buttons beside it or with t and the left or right arrow, and t z; t c and t v copy and
  paste a range. Relative ranges stay relative where they can: the last 6 hours moved back are
  6 to 12 hours ago.
- The time picker searches its quick ranges (with today, this week, month and year so far,
  previous week, month and year, and fiscal quarters and years), lists the ranges you used last
  in this browser, and picks the start and end day on a calendar; it names the time zone the
  times are in.
- Dashboard settings have time options: a time zone and first day of the week for everyone who
  opens the dashboard, the month the fiscal year starts with, a delay that leaves out the newest,
  still incomplete data, the refresh intervals to offer, and a shared cursor that shows the
  pointer's time (and the values) in every time series panel.
- Bar charts show several series side by side per category with a small gap between the bars,
  write large axis values short (25 k, 200 k), can hide the category names and write values above
  bars wherever they fit; the legend can stand on the right as a list or a table. A bar chart of
  one series takes the quiet monochrome look of the time series.
- Bar gauges draw one bar per row for a result with names and values, with each value right after
  its bar's end; the bars share the panel's height, the value grows with them and can take the
  bar's color or be hidden, and names go before or above the bars or can be hidden.
- Pie charts fill their panel and write percentages on the slices where they fit (or beside the
  circle, as before); the legend table on the right lists the value, the share or both, without a
  darker band behind its header.
- Text panels read like a short document: more space between paragraphs and list items, a relaxed
  line height and quieter list markers.
- Time series have a graph style under the field options: lines, bars or points; linear, smooth
  or stepped lines; line width and solid, dashed or dotted lines; no fill, a solid fill or
  hatching, with a fading, hue or threshold gradient; points always, never or when there is room,
  in a size of your choice; gaps connected always or up to a duration, and lines broken where
  points lie too far apart; series stacked normally or to 100 % in groups, positive values
  upward and negative values downward from zero (100 % counts the size of each value, so +5 and
  -5 are +50 % and -50 %); bar alignment and width. Every option can be set per series through an
  override. A stacked line fills down to the series below it point by point and breaks where it
  has no value itself.
- A time series with one series draws it in the quiet look: a light line on dark (dark on light),
  2 px, smooth, with a fading hatch beneath and only horizontal grid lines. Mark a series as
  comparison series and it is drawn muted and dashed beside it (7 px dash, 6 px gap at 2 px,
  growing with the line width; dashed lines you chose yourself use the same pattern); several
  series keep the color palette. Existing dashboards change their look with this: a panel with one series was drawn
  1 px, straight and unfilled in the first palette color. For the old look, set the graph style
  to line width 1, line interpolation linear and fill none, and pick a series color under Color.
- Settings in one place (Settings in the sidebar): sections for the server, your organization
  and yourself, with a search that finds a setting by its German or English name, its
  description or its key and jumps to it; every section and every setting has its own address.
  Changes apply at once with Undo; values from `kalzit.toml` or the environment show as locked
  with their source. On phones the sections become a menu above the page.
- Appearance and brand: default theme, accent color (eight checked colors or your own color,
  refused when its contrast is too low), product name and logo (PNG, JPEG or WebP, in the
  sidebar, on the sign-in page and as the browser tab icon), density, font size, start page,
  time zone and first day of the week, with a live preview. Organizations can set
  their own accent, density, font size, start page, time zone and week start, or follow the
  server.
- The sign-in page can show your own welcome text and a notice, with bold, italic and links, and
  follows the server's default theme until a visitor picks their own.
- Uploading, replacing or removing the logo can be undone.
- Network, TLS, proxy, session, security and log settings from `kalzit.toml` are visible
  read-only in the settings.
- Export settings as a JSON file and import them on another server: the import lists every
  change before anything is applied, applies all of them together and can be undone. Only
  settings you may change are exported, never secrets.
- Updates: under Administration, Updates shows the installed version, looks for new releases on
  GitHub (once a day if you turn it on, stable or preview channel) and shows a new version with its
  release notes, size and verified signature. Every release is signed; Kalzit installs nothing
  whose Ed25519 signature or checksum does not match, and never an older version.
- Download and install with one click on Linux under systemd: Kalzit backs up its database,
  replaces itself, restarts, and returns to the previous version and database on its own if the
  new one does not report healthy in time. Plan an installation for the maintenance window
  instead (02:00 to 04:00 unless you change it).
- Servers without internet access install the same signed packages offline: download the
  `.kalzit-update` file from the GitHub release and drop it on the Updates page.
- Backups before every update, a "Back up now" button and downloads of each backup; the history
  lists every update with who started it, how long it took and how it ended, and returns to an
  earlier version that is still kept.
- Windows and installations Kalzit cannot restart on its own download and verify the release, and
  `kalzit update apply` (with Kalzit stopped) installs it; the next start checks itself and returns
  on its own when it is not healthy. `kalzit update rollback <version>` returns to a kept version.
- Explore keeps a history of the queries you run, visible only to you and kept for 30 days: search
  it, filter by data source, load a query into the editor, run it again or delete it.
- The data source list opens with a status overview (number of sources and kinds, how many are not
  tested, the median response time, the slowest source and any that are down) and lets you search
  by name or kind, filter by status, sort (name, problems first, newest first) and **Test all**.
  **Details** opens a side panel with an overview, **Open in Explore**, and an Access tab that
  shows your own access and who has access beyond their role.
- Adding a data source groups the kinds (Tables, Metrics and search, Documents and graphs, Files
  and APIs) with a search, then guides you through three steps: kind, connection and test. The
  settings come in sections (Connection, Authentication, TLS, Limits, Behavior). PostgreSQL, MySQL
  and MariaDB and MongoDB can also be entered as a connection string; fields and string stay in
  step, a pasted password goes to the password field, and a parameter with no setting is refused
  instead of dropped.
- Colours of a panel are set in one place: a colour scheme (the Kalzit palette, one colour, by
  threshold, or a green-yellow-red, blue or gray ramp), your own colours as `#rrggbb` with a
  contrast check against the panel, and a colour, line style and opacity per series, with the rest
  through overrides. Thresholds can be shown in a time series as lines, areas or both.
- Pin up to 10 dashboards to the sidebar and keep them in your own order (pin button in the
  dashboard tools, **Pinned** in the sidebar). The organization card at the top of the sidebar
  opens the organization menu with your role, its settings, members and teams, and switches to
  another organization; server admins see them all.
- In edit mode a click selects a panel: it shows its size and a small toolbar, and the rail shows
  an inspector for title, description, size and place, data, visualization, repeat and library.
  Panels can carry a description and a transparent background. A version without these fields
  refuses dashboards that use them: before returning to such a version, restore the backup taken
  with the update (the rollback offers it), or clear the description and the transparent
  background of those panels first.
- A data source's page shows its name, status and last test at the top with **Test**, **Open in
  Explore** and a menu with **Duplicate** and **Move to trash**; the settings come in the add
  page's sections, settings you may not change are marked locked, an overview and who has access
  sit beside them, and the trash is at the bottom. Leaving with unsaved changes asks first.
  **Duplicate** starts a new source with the same name and settings, without the secrets.
- Folders in the dashboard list fold and unfold (chevron, or the left and right arrow keys), stay
  as you left them in this browser, and the way to the current folder is always open; **Fold all**
  folds every folder.
- Dashboard settings are a page of their own (`/dashboards/{id}/settings`) with sections for
  general settings, variables, annotations, links, time options, access, versions and JSON.
  **Save…** saves the dashboard with a message, **Apply** in edit mode takes the settings into the
  unsaved dashboard, and leaving with changes asks first.

- Team spaces: a team gets its own area in the folder tree that only its members see and work
  in with their role; other teams see nothing of it until the team shares it (read or edit) through
  Access. Maintainers of a team and admins create team spaces with "Create team space".
- Team ownership in shared folders: under "Team and visibility" a folder or dashboard can belong
  to a team. Everyone with access to the folder reads it and only the team edits and annotates it,
  or, set to "Team only", nobody outside the team sees it. Giving shared content to a team takes
  the right to manage the folder's access (admins, or an admin grant); within what a team already
  owns, its editors decide.
- Moving content out of a team space is for the team's maintainers and admins, and recorded in
  the audit log; editors move within the space.
- The workspace card on top of the sidebar shows the team you work in below the organization's
  name. With more than one team, pick another one or "All areas" in its menu; the Dashboards page,
  the start page lists and where a new dashboard goes follow your choice, which Kalzit remembers
  per organization.
- Admins see and manage every team space; each time they open or change another team's space,
  team-only content or a restricted folder through their admin rights, it is written to the audit
  log. Deleting a team asks who takes over what it owns: another team or the organization.
- Library panels show how many dashboards you may open use them, without counting others.
- A new organization setting puts new dashboards into the team space of the current team.
- Updating adds team ownership to the database on the first start (migration 0014, on SQLite and
  PostgreSQL alike, nothing to do by hand). Existing folders and dashboards keep their access
  unchanged: they belong to no team until someone gives them one. Returning to an earlier version
  afterwards restores the backup taken with the update: team spaces, owner teams and everything
  else changed since are gone, and an earlier version would show team-only content to everyone
  with access to its folder, so do not start one on the updated database without that backup.
- A query with more rows than the row limit answers right away on PostgreSQL and MySQL/MariaDB:
  the database stops at the limit instead of sending every row first.
- A dashboard opening many panels on one data source connects once instead of once per panel.
- Results are now counted by the memory they take, not by their JSON text: every value counts
  at least 32 bytes, plus its text and document entries. So many small values or large documents
  no longer use far more memory than the limit allows. The default limit per request rises from
  50 MiB to 128 MiB to make up for it; change it under Settings > Server > Data sources and targets
  ("Result memory per request").
- Signing in and permission checks stay fast on SQLite while other changes wait to be saved.
- The audit log opens and filters quickly on large logs (migration 0015 adds indexes, nothing to
  do by hand).
- Dashboards that refresh often and repeated Explore runs no longer pile up old results in the
  browser's memory.

- Large exports no longer fill the server's memory: CSV, JSON and Excel files are made on disk
  and then sent, Excel files are no longer limited to a million cells, a slow download does not
  hold up other users' exports (everyone has one export at a time), and downloads that stall are
  given up.
- Data sources in the trash can be deleted for good, with their stored secrets (not while a
  dashboard or library panel still uses them; the answer says how many).
- The add and edit forms of a data source test the settings you entered before anything is saved,
  with the same rules as saving; a stored password you leave out is used from the saved source.
  Testing is limited to 20 times a minute.

## Fixed

- Names and texts cut off with "…" show their full text as a tooltip.
- Empty lists offer the next step: add the first data source, create the first playlist, create a
  dashboard in an empty folder, clear a search that found nothing.
- Unavailable menu items can be reached with the arrow keys and are read as unavailable.
- Tabs jump to the first and last tab with Home and End.
- Dialogs keep the Tab key inside also after a click on their background.
- The star on a dashboard keeps its name ("Favorite"); screen readers hear whether it is on.
- "Nothing found" in the time picker, the settings search and table filters is read by screen
  readers.
- Undoing a change to a setting that had no value of its own brings the default back instead of
  storing a copy of it, and a change made while another setting is still saving is no longer lost.
- A setting saved from a page opened before someone reset it is refused instead of silently
  replacing the default.
- Restoring an old dashboard version no longer replaces a save made after the history was opened.
- "now/h" and "now/m" in the hour that repeats when the clocks go back stay in that hour.
- Prometheus points stay on the same times from one refresh to the next, and infinite values come
  with a notice instead of empty points without a word.
- The start page's activity total matches its bars.
- Exporting a panel that shows a library panel exports the library panel's data.
- Long panel texts are cut without breaking a character apart.
- A downloaded update is written to disk completely before it counts as ready to install.
- Starting an older Kalzit on a database a newer version updated says so and names the backup.
- The collapsed sidebar's tooltip disappears when the sidebar scrolls.
- The library panel search waits for a pause in typing.
- English texts use typographic apostrophes; German texts name keys as on a German keyboard.

- The filter bar of a dashboard is one tidy row: every variable is a compact control of the same
  height, a variable with several values is a picker with a summary ("Nord, Ost +2") and a menu of
  checkboxes instead of a tall list box, and links sit in the bar as small buttons or in one
  **Links** menu, so the time controls stay on the same row.
- Bar charts and histograms round their value axis out to the next tick, so the tallest bar and
  bars below zero are drawn whole instead of cut off at the last tick.
- Bar gauges with one field per bar compare fields of the same unit on one scale; before, every
  bar of a reduced value could look full.
- The tooltip of bar charts, bar gauges and pies no longer hides the name of the item in the
  middle of a chart.
- Panels and Explore queries on CSV and JSON files and HTTP JSON sources run instead of saying
  that there is no query yet.
- Creating or changing a library panel checks its options and field options like a dashboard save, and names the panel and the option it refuses; a stored library panel can still be saved while those stay as they are.
- Refreshing a dashboard keeps every panel's data on screen until the new data arrives: charts
  stay, and tables keep their sort, scroll position and page. Only the panel title dims while it
  loads.
- Two people editing the same data source no longer overwrite each other: a save or delete from
  a page opened before the other change shows the change, with the choice to load it or to save
  anyway. A password is never stored for a host it was not entered for.
- After clicking a node in a graph panel, Ctrl+K, ?, / and the other shortcuts work again; Escape
  clears the selection while the graph has the focus.
- Data sources can no longer reach the cloud metadata addresses of Alibaba Cloud, the Azure
  WireServer, Oracle Cloud's second address and the IPv6 address of Google Cloud, also when
  written in another IPv6 form or tunnelled through 6to4, Teredo or NAT64.
- Linking a library panel to a dashboard, or changing a variable a linked library panel reads,
  needs the right to query its data source, as changing a panel's own query does.

- The settings navigation stays beside the section while it scrolls and scrolls on its own when
  it is taller than the window.
- The menu of a pinned dashboard in the sidebar opens beside it, whole, instead of as a clipped
  sliver under "Pin dashboard"; toolbar menus near the bottom of the window open upwards.
- The SQLite time filter finds rows whose times are stored as Unix seconds or milliseconds, and
  no longer cuts ISO times written with a "T" at the edges of the range.
- SQLite NUMERIC and DECIMAL columns keep their decimals when the first rows hold whole numbers.
- NUMERIC, DECIMAL and PostgreSQL MONEY values keep every digit in tables, in stats showing the
  last, smallest or largest value, and in exports, instead of being rounded to the nearest
  floating point number; sums, averages and charts still calculate with floating point numbers.
- The SQLite time filter can use an index on the time column again.
- DATE columns from PostgreSQL, MySQL, MariaDB and SQL Server show the stored day in every time
  zone instead of the day before west of UTC, and charts draw them at that day's midnight.
- Prometheus `$__interval` and `$__rate_interval` follow the step actually asked for, also when
  the minimum step or the point limit raises it.
- Calculated fields read times in the dashboard's time zone (else yours) and start weeks on the
  first day of the week set there, in panels and in exports alike.
- A panel with its own range and a time shift ("last 24h, shifted by 1d") shows a full 24 hours
  on days when the clocks change.
- Changing an annotation's time takes it in the time zone the dialog shows, also when it differs
  from the computer's.

- In a window about 900 px wide, the dashboard toolbar wraps its buttons instead of reaching past
  the window's edge, so its More menu opens again.

- Deleted data sources no longer keep their stored passwords forever: a data source left in the
  trash for 30 days is deleted with its passwords and keys, unless a dashboard or library panel
  still uses it.
- SQLite and file data sources can no longer open Kalzit's configuration file, TLS key and
  certificate, systemd credentials, or a hard link (a second name of a file such as Kalzit's own
  database), even inside an allowed folder.
- Over HTTPS the session cookie is marked secure with the `__Host-` prefix, so a site on another
  subdomain cannot set or replace it. Sessions started over HTTPS before this update end once;
  sign in again.
- Failed sign-ins from IPv6 are counted per network (/64), so changing the address does not give
  new attempts; many addresses can no longer reset an account's attempts.
- More functions that read the server's files are refused in SQL queries (PostgreSQL directory
  listings, SQL Server file system functions).
- Moving a stored query to another panel or showing a hidden one now needs the right to query its
  data source, like changing the query.
- Signing out is recorded in the audit log.

## Checklist for Windows (manual)

- Put a hard link to a CSV file into a folder allowed in `datasources.file_dirs`
  (`mklink /H link.csv original.csv`) and check that a file data source refuses `link.csv`.
- Behind IIS or another proxy listed in `security.trusted_proxies`, sign in over HTTPS and check in
  the browser's developer tools that the cookie is `__Host-kalzit_session` and marked Secure.
- With Windows set to a time zone west of UTC (for example Pacific Time), open a table of a
  PostgreSQL or SQL Server `DATE` column and check that it shows the stored days, not the day before.
- Export a panel with a calculated field `day(zeit)` as CSV from a dashboard set to
  America/New_York and check that the file shows the same days as the panel.
- Open the same data source in two browsers. Save a new port in the first, then save a new name
  in the second: the second shows that the source changed in the meantime. "Load saved version"
  shows the new port; "Save mine over it" keeps both changes.
- Set a dashboard with a chart and a sorted, scrolled table to refresh every 5 seconds: no panel
  shows "Loading" after the first load, and the table keeps its sort and scroll position.
- Install as a service with a virtual account, start it, and check that
  `%ProgramData%\Kalzit\data` exists and only SYSTEM, Administrators and the service account have
  access (`icacls "%ProgramData%\Kalzit\data"`).
- Check that `%ProgramData%\Kalzit` grants Users read access only.
- Grant Users write access to the data directory (`icacls ... /grant Users:(W)`), restart the
  service, and check that it refuses to start with a message that names `icacls`; remove the
  entry again and check that it starts.
- Open the data directory in a non-elevated Explorer, click "Continue", restart the service and
  check that it refuses to start; remove the added entry with `icacls ... /remove <account>`.
- Exclude `kalzit.db`, `kalzit.db-wal` and `kalzit.db-shm` in the data directory from virus
  scanning (real-time protection), and check that saving still works quickly afterwards.
- Start Kalzit in a console window, close the window, and check that `kalzit.db-wal` is gone
  afterwards (a clean stop).
- Export a dashboard in Edge, import the file again and check that its data sources are matched
  by kind and name.
- Play a playlist in TV mode for a few minutes and check that the controls hide and come back
  with the mouse or a key.
- In Edge on a 1920 px wide screen, open a dashboard and check that it fills the width next to the
  sidebar; drag the window narrower and check that the charts follow without flickering.
- Stop Kalzit, back up `kalzit.db`, `kalzit.db-wal` and `kalzit.db-shm` together, start it again
  and check that sign-in works.
- Back up while running with `sqlite3 kalzit.db ".backup backup.db"` and restore the backup into
  a fresh data directory together with the key file, copying (not moving) the files.
- Allow a folder under `datasources.file_dirs`, add a CSV file saved by German Excel from it as a
  data source (`C:\Daten\umsatz.csv`), and check in Explore that its columns and decimal commas
  read right; a file outside the folder is refused.
- Export a panel as CSV in German and open it in Excel by double-click: umlauts, decimal commas
  and columns are right; open the Excel export and check that times and numbers are cells of
  their type.
- Open the command palette with Ctrl+K in Edge and Firefox on Windows, and check that it opens
  instead of the browser's address search, also with a German keyboard layout.
- Press ? with a German keyboard layout (Shift+ß) and check that the shortcuts help opens.
- Press / with a German keyboard layout (Shift+7) outside a text field and check that the search
  opens.
- Pick a time zone other than the computer's on the account page and check that times on the
  dashboard list, in a time series chart, in "Today" and in the audit log's day filter follow it.
- In Edge, open a panel in the editor, drag both separators and move them with the arrow keys,
  change the title, reload the page and check that the editor opens again with the same sizes and
  the changed title; press Esc and check that the dashboard shows the change as unsaved. Add a new
  panel, press the browser's back button and check that Kalzit asks before dropping it.
- On the sign-in page in Edge, turn Caps Lock on, type into the password field and check that the
  warning shows below it and goes away when Caps Lock is off; check that Edge's own reveal button
  does not appear next to Kalzit's.
- In Edge with a German keyboard layout, press t and then the left arrow on a dashboard and check
  that the time range moves back; press t and then c, and check that pasting into Notepad gives
  the range.
- Set a dashboard's time zone to one other than the computer's and its fiscal year to April, pick
  "This fiscal year" and check that the range starts on 1 April at midnight in that zone.
- In Edge, open a dashboard with a bar chart of several series, a bar gauge and a pie with their
  legends on the right; check that the bars stand side by side with short axis values, that the
  gauge's values grow and shrink with the panel's height, and that the pie's percentages sit on
  its slices; make the window narrow and check that the legends move below the drawings.
- In Edge with Kalzit's high contrast theme, open a time series with one series and check that
  the hatch under the line stays visible; switch Windows' "Animation effects" off and check that
  the charts still draw at once.
- In Edge, upload a PNG logo in Settings, Appearance and brand, and check that it shows in the
  sidebar, on the sign-in page and as the tab icon; export the server settings, import the file
  on a second Kalzit and check the list of changes before applying it.
- Updates on Windows: open Administration, Updates, upload the `.kalzit-update` package of a newer
  release for Windows x64 and check that it shows as verified and that the page names
  `kalzit update apply`. Stop Kalzit, run `kalzit update apply` in an elevated prompt, start
  Kalzit, and check that it runs the new version and that the history lists the update. Install a
  second newer release the same way, then stop Kalzit, run `kalzit update rollback <first updated
  version>`, start it, and check that this version runs with your data; `kalzit update rollback`
  to the version you installed by hand is refused, since no signed manifest was kept for it.
  Upload a package for Linux and check that it is refused with the platform named. Put an unknown
  key into `kalzit.toml` right after `kalzit update apply` and start Kalzit: it returns to the
  previous version on its own.
- Teams in Edge: create two teams with one member each, let each maintainer create a team space
  and a dashboard in it, and check that neither sees the other's space in the tree, the dashboard
  list or the command palette. Share one space with the other team for reading and check that the
  dashboard opens but cannot be saved. Switch the team in the workspace card and check that the
  Dashboards page follows. Delete a team that owns a space: Kalzit asks to hand it over first.
- Add a data source in Edge from a PostgreSQL connection string with a password and check that the
  password field shows dots and the string does not show the password again; a string with a
  broken %-escape names the part.
- Pin a dashboard from its page, reload, reorder the pins with the keyboard and check that the
  order stays; pin a tenth and check that the pin button says the most is reached.
- Pick a custom colour in the panel editor on a dashboard in the dark and the light theme and
  check that it stays the same and that a low-contrast colour shows the warning.
- Start an older `kalzit.exe` on a database this version has migrated: it refuses to start with
  "written by a newer Kalzit" and names `updates\backups` in the data directory.
