# Kalzit 0.5.3

A security release: an organization that requires a second factor now checks every browser
session, not only the account, setting up a first second factor asks for the password, and
refusals tell less about other accounts.

## Improved

- Organizations that require a second factor let a session in only once it proved one: by
  signing in with it, by setting it up in that session, or by confirming it. A member who has a
  second factor and sees "This organization requires a second factor" chooses "Confirm your
  second factor" and enters a code or uses a passkey; "Set up now" stays for members without one.
- Setting up your first second factor asks for your password first, so a signed-in browser
  someone else took over cannot set up a factor of its own. Setting it up signs you out on every
  other device and browser.
- Accounts that sign in only through a provider or directory set up their first second factor
  right after a sign-in. An older session sees "Sign in again" first.
- A provider's second factor counts only while that provider is enabled and still trusted for it.
  After the update, members who rely on their provider's second factor may be asked to confirm or
  sign in again once.
- Before an organization turns password sign-in off, its admins see which owners and admins have
  no sign-in through a provider or directory into it, and turn it off only after confirming. A
  server admin can put the rule back under Verwaltung > Organisationen.
- "Add member" gives the same answer for an address without an account as for one that cannot be
  added directly, and offers the invitation for both. The audit log keeps the reason.
- SCIM gives the same neutral answer for every account that cannot be linked and for an address
  change to an address another account has; the audit log keeps the reason.
- The outbound proxy is also refused when its name resolves to Kalzit's own address, its listener
  or its own database server, and numeric addresses such as `2130706433` count as the address they
  mean.
- Behind a reverse proxy, a scheme a client sends itself in `X-Forwarded-Proto` no longer counts
  when the proxy appends to that header. The admin guide says to configure the proxy to overwrite
  it.
- A reverse proxy that sends a broken `Forwarded` header fills the log with one warning a minute,
  with the number of refused requests, instead of one per request.

## Fixed

- A stolen browser session with only the password could set up a second factor and then enter an
  organization that requires one. It cannot any more, and sessions that signed in with only a
  password before the account got a second factor stay out of such an organization until they
  confirm it.
- An account an organization's SCIM made is linked to a provider's sign-in by its email address
  only through a group mapping into that organization, not through the rule for people without a
  mapped group.
- The private key of a TLS certificate read from files is wiped from memory after each reload.

## Checklist for Windows (manual)

- Second factor per session: in an organization with "Zweiter Faktor Pflicht" "Für alle", sign in
  as a member without a second factor in two browsers. In the first, open Einstellungen >
  Anmeldung und Sicherheit, choose "Einrichten" for the app and check that it asks for the
  password first and refuses a wrong one. Finish the setup and check that the organization opens
  in that browser and that the second browser is signed out.
- Confirm instead of set up: as a member with a second factor, open the organization in a session
  that has not confirmed it (sign in again after the rule was turned on, or wait for a provider
  sign-in), check that the page offers "Zweiten Faktor bestätigen", confirm with the app's code
  and check that the organization's pages load.
- Password sign-in off: as an organization admin signed in through a provider, set
  Einstellungen > Organisation > "Anmeldung mit Passwort" to "Aus" while another owner has only a
  password. Check that the dialog "Anmeldung mit Passwort abschalten?" names that owner, that
  "Abbrechen" changes nothing, and that "Trotzdem abschalten" saves it.
- Sign-in through a provider: as a member without a password and without a second factor, wait
  more than five minutes after signing in, open Einstellungen > Anmeldung und Sicherheit and
  choose "Einrichten". Check that the dialog offers "Neu anmelden", and that after signing in
  again through the provider the setup goes through.
- Add member: add an address no account has and check that the dialog says to invite the person,
  the same text as for a member of another organization, and that the audit log shows
  "Mitglied nicht hinzugefügt".
- Outbound proxy: set Einstellungen > Netzwerk, HTTPS und Proxy > "Ausgehender Proxy" to
  `http://<this computer's name>:<Kalzit's port>` and check that it is refused with a clear
  message.
