## Improved

- Explore and the panel editor have a pattern builder for Neo4j, Memgraph and TigerGraph: "Pattern | Cypher" (or "Pattern | GSQL") above the query. Draw nodes and edges, pick labels and edge types from the source's schema (the types that exist between two labels come first), set direction, path length, optional parts, conditions with comparisons that fit each property's data type, and the most matches. The pattern reads as a sentence, and the query Kalzit writes for it stands beside it, always; "Edit as Cypher" takes it into the text, and "Open as pattern" reads a text back when the whole query can be drawn, or says what cannot be drawn and where.
- Values in a pattern can be variables (type `$name`): in Explore with a sample value, on a dashboard from the dashboard variable of the same name. "Paste values" turns a column from a table into one list variable and says how many values it found, how many repeats and empty lines it left out, and which values do not fit the type.
- A pattern or a Cypher query with variables can be saved as a search template, with a label per input and, for text and numbers, a choice from the values of one property. Everyone who may read it, viewers too, enters the inputs and runs it on its page, which also shows what the search does, its pattern and its query.
- Graph sources show their schema beside the result: labels and edge types as a graph with their counts, or as a list per label with each property's data type; where the schema comes from and how fresh it is is said under it, a sample is called a sample, and a label without a count can be counted on request.
- The "Plan" tab shows how Neo4j and Memgraph work through a Cypher query, as a tree with a sentence per step: "Plan only" without running it, "With measurement" after saying that the query runs; a few hints in plain language say what may help. For GSQL the tab says that TigerGraph has no general query plan.
