# Kalzit 0.3.2

## Improved

- Signing in on a browser that is not yours: tick "This is not my browser" and Kalzit does not
  remember it as one of your devices. The account menu also offers "Sign out and forget this
  browser". A plain sign-out keeps your own browser remembered, as before.
- Setting a password during setup, when an admin resets one or when you change your own no longer
  waits behind a flood of sign-in attempts.

## Fixed

- A data source plugin that was removed could be installed again from a package signed by
  someone else, which then received the passwords of the existing data sources of that plugin.
  A reinstall now needs the same signature as before; a different publisher needs an admin's
  explicit confirmation and clears the stored passwords of those data sources, which must then
  be entered again.

## Checklist for Windows (manual)

- Sign-in on Windows: sign in with "This is not my browser" ticked, then check in the browser's
  developer tools that no `kalzit_device` cookie is stored. Sign in again without it, choose
  "Sign out and forget this browser" in the account menu and check that the cookie is gone. Sign
  in once more and sign out normally: the cookie stays.
- Plugins on Windows: install a signed data source plugin, add a data source with a password,
  remove the plugin and install it again from a package signed with another trusted key
  (`POST /api/admin/plugins`). Check that it is refused, that it installs when repeated with
  `?confirmPublisherChange=true`, and that the data source asks for its password again.
- Passwords on Windows: as a server admin, reset a user's password and change your own, and check
  that both finish quickly.
