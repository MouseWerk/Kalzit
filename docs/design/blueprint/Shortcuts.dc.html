Tastenkürzel: die Hilfe neu, mit Korrekturen (Entwurf zur Freigabe)

Die Hilfe hinter „?“ wird ein durchsuchbarer Dialog, der zuerst zeigt, was an der Stelle gilt, an der man gerade ist, mit Tasten in der Facetten-Sprache der Icons, richtigen Namen je Sprache und Plattform und klar gezeichneten Folgen. Vorne steht, was heute nicht stimmt; am Ende, wie Features ihre Kürzel künftig einmal anmelden, damit Liste und Code nicht mehr auseinanderlaufen. Beispieldaten; Produktcode ändert dieses Board nicht.

1

Bestand: was heute nicht stimmt

Aus dem Code gelesen (ShortcutsHelp.tsx, AppShell.tsx, timeShortcuts.ts, panelShortcuts.ts, sidebarState.ts, Explore, Graph auf m8/graph-canvas); die laufende Oberfläche wurde dafür nicht gestartet. „Verdacht“ heißt: im Code so angelegt, im Browser noch zu bestätigen.

Tastatur und Screenreader

Wie die Hilfe angesagt und ohne Maus bedient wird.
Öffnen
? außerhalb von Eingabefeldern, Hilfe-Menü, Palette. Der Fokus geht in das Suchfeld. Angesagt wird: „Tastenkürzel, Dialog. Kürzel oder Taste suchen, Suchfeld. 62 Kürzel in 14 Bereichen, zuerst: Dashboard bearbeiten.“
Reihenfolge mit Tab
Suchfeld, Schließen, Bereichsliste (ein Tab-Stopp, darin Pfeil auf und ab), Liste (ein Tab-Stopp, rollt mit Pfeil auf und ab, Bild auf und ab, Pos1, Ende), „Einstellungen für Tastenkürzel“. Der Fokus bleibt im Dialog.
Bereich wählen
Eingabe auf einem Bereich rollt die Liste dorthin und setzt den Fokus auf dessen Überschrift. Im Suchfeld springt Pfeil ab in die Liste.
Schließen
? noch einmal (nicht während im Suchfeld getippt wird: dort ist „?“ ein Zeichen), Esc (leert erst die Suche), der Knopf oben, Klick auf den Hintergrund, Zurück im Browser. Der Fokus kehrt zum Element von vorher zurück.
Aufbau für Screenreader
Dialog mit Namen; Bereiche als Navigation „Bereiche“ mit aria-current; jede Gruppe ist ein Abschnitt mit Überschrift (h3) und einer Beschreibungsliste. So springt man mit der Überschriften-Taste des Screenreaders von Bereich zu Bereich.
Wie eine Zeile klingt
„Befehlspalette öffnen oder schließen: Steuerung plus K, oder Schrägstrich.“ · „Zeitraum zurückschieben: T, dann Pfeil links.“ · Mac: „Befehl plus Umschalt plus S“. Jede Taste trägt ihren ausgeschriebenen Namen; Zeichen wie ⌘ ? / werden nie roh vorgelesen.
Suche
Die Trefferzahl steht sichtbar im Feld und wird mit kurzer Verzögerung höflich angesagt: „6 Kürzel“. Bei null Treffern: „Kein Tastenkürzel für export“.
An den Knöpfen der App
aria-keyshortcuts nur für einzelne Tastenkombinationen, mit der Taste der Plattform (Meta+K auf dem Mac). Folgen stehen im Namen: „Zeitraum zurück, T, dann Pfeil links“. Menüeinträge und Palettentreffer tragen ihr Kürzel ebenfalls.
Einzelne Tasten
Kürzel aus einer Taste wirken nie in Feldern, Editoren, Auswahllisten und unter offenen Dialogen, nie bei gehaltener Taste, und lassen sich abschalten (Frame 12).

Damit die Liste nie vom Code abweicht: ein Register

Heute steht die Liste von Hand in ShortcutsHelp.tsx („ein neues Kürzel wird auch hier eingetragen“), die Wirkung in über zwanzig einzelnen Zuhörern. Künftig meldet jedes Feature sein Kürzel einmal an; Wirkung, Hilfe, Tooltips, aria und Handbuch lesen dieselbe Definition.
// ui/src/shortcuts/registry.ts: hier entsteht jedes Kürzel
defineShortcut({
  id:     "time.back",
  area:   "time",                    // Gruppe in der Hilfe
  keys:   sequence("T", "ArrowLeft"),// oder combo("Mod", "K")
  label:  "shortcuts.time.back",     // Katalogschlüssel, de und en
  when:   "dashboard.timeControls",  // wo es gilt, was oben steht
  scope:  "page",                    // global | page | focus
  note:   "shortcuts.note.wide",     // Notiz an der Zeile, optional
});

// im Feature: nur noch die Wirkung
useShortcut("time.back", () => shiftRange(-1));

// in der Oberfläche: nur noch die Kennung
<Keys id="time.back" />           // Tooltip, Menü, Palette, Hilfe
